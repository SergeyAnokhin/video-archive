# Code Map — Backend HTTP API (routers)

Part of the [code map](code-map.md). **Update this file whenever router files are added, moved, or removed.** The routers stay thin — domain logic lives in the modules mapped in [code-map-backend.md](code-map-backend.md). Keep entries short: endpoints plus genuinely non-obvious behavior only.

## `backend/app/routers/`

| Path | Role |
| --- | --- |
| [`backend/app/routers/health.py`](../backend/app/routers/health.py) | `GET /api/health`. |
| [`backend/app/routers/system_stats.py`](../backend/app/routers/system_stats.py) | `GET /api/system/stats` — `{cpu_percent, memory_rss_bytes, memory_percent, smb_bytes_read_total, timestamp}` for the top-bar resource widget (`BackendHealthWidget.tsx`). `cpu_percent` is normalized to a 0-100 share of total system CPU (`psutil`'s raw per-process figure is relative to one core and can exceed 100%). `smb_bytes_read_total` is a cumulative in-memory counter (`app/sources/smb_stats.py`, fed by `SMBBackend.read_bytes()`/`open_range()`) that resets on backend restart; the frontend derives a bytes/sec rate from two polls itself. Polled every 5s — in `_QUIET_ROUTES` alongside `/api/health`. |
| [`backend/app/routers/app_info.py`](../backend/app/routers/app_info.py) | `GET /api/app/info` (version, active source, DB status, queue summary, ffmpeg availability). `GET /api/app/network-info` (`{lan_addresses, frontend_port, backend_port}` for Settings → Network; backend port read off the request itself, correct through the Vite proxy). |
| [`backend/app/routers/source.py`](../backend/app/routers/source.py) | `GET/PUT /api/source`, `POST /api/source/test-connection`, `POST /api/source/reconnect`. `PUT` upserts a saved `sources` row matching `(protocol, host, port, root_path)` then runs `source_switch.switch_active_source()`; response includes `detected_backups`/`auto_restored`/`scan_job`. SMB `root_path` is `share[/subpath]`; credentials go to `secrets_store` per source id. `webdav` → 400 `unsupported_protocol`. Reconnect is a no-op for `local`. The connect scan runs as a background `rescan` job (`scan_job` in the response), not synchronously — the frontend follows its progress the same way as any other job (top-bar activity indicator, Jobs modal) instead of blocking on the request. |
| [`backend/app/routers/sources.py`](../backend/app/routers/sources.py) | Saved sources: `GET /api/sources` (each with `preview_cache` stats — live for the active source only, `{size_bytes: 0, file_count: 0}` for inactive ones), `POST /api/sources/{id}/activate` (no-op if already active, else `switch_active_source()`), `DELETE /api/sources/{id}` (400 `active_source` for the active one; removes the saved-source row + credentials only, never touches that source's disk), `DELETE /api/sources/{id}/preview-cache` (400 `not_active_source` unless it's the active source; clears its `.video-archive/previews/` GIFs via `preview_assets.clear_for_active_source()` and resets the has-preview DB flags so the next run regenerates). |
| [`backend/app/routers/tree.py`](../backend/app/routers/tree.py) | `GET /api/tree` — recursive tree from `path`, optional `depth`, `include_status`, and `include_top_tags` (opt-in, same convention as `include_status` — each node gets `top_tags`, see `tags.top_tags_for_directory_subtree()`). |
| [`backend/app/routers/directories.py`](../backend/app/routers/directories.py) | `GET /api/directories/children` — one directory's subfolders + files (each with `duration_seconds`/`variant_tags`/`ai_tags`; optional `include_top_tags` adds each subfolder's dynamic `top_tags`). `GET /api/directories/preview.gif?path=` (folder GIF read from the source's `.video-archive/previews/`). `POST /api/directories`, `DELETE ?path=` (empty only), `PUT /favorite`, `GET /favorites` — delegating to `directory_ops.py`. `GET /search?q=` — paginated folder-name search for the `path:` scope. |
| [`backend/app/routers/files.py`](../backend/app/routers/files.py) | `GET /api/files` (directory/recursive/search/tag filters, paginated), `GET /api/files/{id}`. Preview serving via `_preview_source_row()` (a variant borrows its original sibling's asset): `/preview` + `/preview.jpg` read the collage from the source, `/preview.gif` from the source's `.video-archive/previews/`. `GET /{id}/tags`, `POST/DELETE /{id}/tags[/{tag_id}]` (manual ad-hoc assign, `score=100`), `POST /{id}/tags/user-defined`, `GET /{id}/similar`, `GET /{id}/media-info` (on-demand ffprobe), `DELETE /{id}` and `POST /{id}/move` (delegate to `file_ops.py`). |
| [`backend/app/routers/playback.py`](../backend/app/routers/playback.py) | `GET /api/files/{id}/playback` (mode + stream URL + direct path) and `GET /api/files/{id}/stream` — a manual Range-aware `StreamingResponse` over `access.open_range()`, one code path for both protocols; `_parse_range()` handles all three `bytes=` forms. |
| [`backend/app/routers/playback_settings.py`](../backend/app/routers/playback_settings.py) | `GET/PUT /api/playback-settings`. |
| [`backend/app/routers/conversion_profiles.py`](../backend/app/routers/conversion_profiles.py) | `GET/POST /api/conversion-profiles`, `PUT/DELETE /api/conversion-profiles/{id}`. |
| [`backend/app/routers/conversion_settings.py`](../backend/app/routers/conversion_settings.py) | `GET/PUT /api/conversion-settings`. |
| [`backend/app/routers/preview_layouts.py`](../backend/app/routers/preview_layouts.py) | `GET/POST /api/preview-layouts`, `PUT/DELETE /api/preview-layouts/{id}` (409 `preset_protected` for built-ins, 400 `invalid_layout`), stateless `POST /api/preview-layouts/preview` (live tile geometry for the editor). |
| [`backend/app/routers/preview_settings.py`](../backend/app/routers/preview_settings.py) | `GET/PUT /api/preview-settings` — PUT is a full replace, the frontend always sends the merged object. |
| [`backend/app/routers/tags.py`](../backend/app/routers/tags.py) | `GET /api/tags` (`query`/`active_only`/`limit`/`category="ai"\|"user"` — one pool, default `"ai"`), `GET /api/tags/used` (any pool, usage-ordered — feeds every add-tag autocomplete), `POST /api/tags` (409 on duplicate; pool flags + optional `color`), `PUT/DELETE /api/tags/{id}`. Every tag response includes `color` (stored or `tags.resolve_tag_color()` fallback). |
| [`backend/app/routers/tagging_settings.py`](../backend/app/routers/tagging_settings.py) | `GET/PUT /api/tagging-settings` (includes `request_timeout_seconds`, user request -- Tag Lab's direct provider call timeout, default 30); `POST /api/tagging-settings/preview` — stateless "what the model sees" demo: builds real tagging images (`app/tagging.py`) from a given file id with arbitrary (possibly unsaved) sample-frame-count/collage/resolution params, returned as base64 JPEG data URLs + pixel dimensions. |
| [`backend/app/routers/tag_lab.py`](../backend/app/routers/tag_lab.py) | The synchronous single-file alternative to `POST /jobs/tag-file`: `POST /files/{id}/tag-lab/prepare` (`{images, prompt}` only, no provider call), `POST .../run` (`{provider_entry_id}` → `run_id` + images/prompt/raw reply/full provider JSON/usage/ranked tags, nothing written), `POST .../apply` (writes `file_tags`, records the apply KPI against `run_id`). A `tag_lab_failed` error also carries `raw_response`/`raw_full_response` when the provider returned something before parsing failed. `POST /tag-lab/runs/{run_id}/feedback` — like/dislike one suggested tag. |
| [`backend/app/routers/providers.py`](../backend/app/routers/providers.py) | `GET/POST /api/settings/provider-entries`, `PUT/DELETE .../{id}` (keys never echoed — only `has_api_key`/`key_suffix`), `POST .../reorder`, `POST .../models` / `.../{id}/models`, `GET .../export` (**includes plaintext keys** — deliberate, frontend warns first), `POST .../import`. `GET /api/settings/provider-usage`; `GET/PUT /api/settings/model-pricing` + `POST .../refresh-openrouter`; `GET /api/settings/model-ratings`. |
| [`backend/app/routers/jobs.py`](../backend/app/routers/jobs.py) | Job endpoints: `GET /api/jobs` (+ filters), `GET /{id}`, `GET /{id}/items`, `POST /{id}/cancel\|pause\|resume\|restart` (409 `job_not_pausable`/`job_not_resumable`), `DELETE /{id}`, `DELETE /api/jobs` (clear finished). Triggers: `rescan-directory`, `convert-directory`/`convert-file` (`variants` requires `mode: "test"`), `preview-directory`/`preview-file`, `tag-directory`/`tag-file` (400 `no_provider_configured`/`empty_tag_vocabulary`; the actual entry is resolved live by the worker), `cleanup-stale-records`, `optimize-database`. `GET/DELETE /api/jobs/batch-submissions[/{id}]` — declared *above* `GET /jobs/{id}` because a literal path segment must precede a same-method `/{id}` route or Starlette swallows it as an id. |
| [`backend/app/routers/logs.py`](../backend/app/routers/logs.py) | `GET /api/logs` (filters: `job_id`, `file_id`, `level`, `limit`) and `GET /api/logs/stream` — SSE polling `app_events` past the last-seen rowid every 0.5s. |
| [`backend/app/routers/backups.py`](../backend/app/routers/backups.py) | `GET /api/backups`, `POST /api/backups` (creates a `backup` job), `POST /api/backups/restore` (creates a `restore` job), `DELETE /api/backups/{id}` (synchronous). Source switching calls `app/backup.py` directly, not through here. |
| [`backend/app/routers/backup_settings.py`](../backend/app/routers/backup_settings.py) | `GET/PUT /api/backup-settings`. |
| [`backend/app/routers/interface_settings.py`](../backend/app/routers/interface_settings.py) | `GET/PUT /api/interface-settings` — the request model is built with `pydantic.create_model()` from `interface_settings.py`'s field/range constants, so validation and defaults stay in sync automatically. |
| [`backend/app/routers/performance_settings.py`](../backend/app/routers/performance_settings.py) | `GET/PUT /api/performance-settings`. |
| [`backend/app/routers/app_settings.py`](../backend/app/routers/app_settings.py) | `GET /api/settings/app-settings/export` (tags + conversion profiles + preview layouts + every settings singleton, as a downloadable JSON file), `POST /api/settings/app-settings/import` (same shape back in; returns `{tags_upserted, profiles_created, layouts_created, settings_applied}`). Thin wrapper over `app/app_settings.py`. |
