# Code Map — Backend HTTP API (routers)

Part of the [code map](code-map.md). **Update this file whenever router files are added, moved, or removed.** The routers stay thin — domain logic lives in the modules mapped in [code-map-backend.md](code-map-backend.md). Keep entries short: endpoints plus genuinely non-obvious behavior only.

## `backend/app/routers/`

| Path | Role |
| --- | --- |
| [`backend/app/routers/health.py`](../backend/app/routers/health.py) | `GET /api/health`. |
| [`backend/app/routers/app_info.py`](../backend/app/routers/app_info.py) | `GET /api/app/info` (version, active source, DB status, queue summary, ffmpeg availability). `GET /api/app/network-info` (`{lan_addresses, frontend_port, backend_port}` for Settings → Network; backend port read off the request itself, correct through the Vite proxy). |
| [`backend/app/routers/source.py`](../backend/app/routers/source.py) | `GET/PUT /api/source`, `POST /api/source/test-connection`, `POST /api/source/reconnect`. `PUT` upserts a saved `sources` row matching `(protocol, host, port, root_path)` then runs `source_switch.switch_active_source()`; response includes `detected_backups`/`auto_restored`. SMB `root_path` is `share[/subpath]`; credentials go to `secrets_store` per source id. `webdav` → 400 `unsupported_protocol`. Reconnect is a no-op for `local`. The connect scan is synchronous. |
| [`backend/app/routers/sources.py`](../backend/app/routers/sources.py) | Saved sources: `GET /api/sources` (each with `preview_cache` stats), `POST /api/sources/{id}/activate` (no-op if already active, else `switch_active_source()`), `DELETE /api/sources/{id}` (400 `active_source` for the active one; removes row + credentials + preview cache, never touches the source's disk), `DELETE /api/sources/{id}/preview-cache` (clears the cache; for the active source also resets the has-preview flags so the next run regenerates). |
| [`backend/app/routers/tree.py`](../backend/app/routers/tree.py) | `GET /api/tree` — recursive tree from `path`, optional `depth`, `include_status`, and `include_top_tags` (opt-in, same convention as `include_status` — each node gets `top_tags`, see `tags.top_tags_for_directory_subtree()`). |
| [`backend/app/routers/directories.py`](../backend/app/routers/directories.py) | `GET /api/directories/children` — one directory's subfolders + video files, each file carrying `duration_seconds`, `variant_tags`, `ai_tags`, and a variant's borrowed `has_preview_asset` (`media.resolve_variant_preview_flags()`); optional `include_top_tags` adds each subfolder's `top_tags` (dynamic, uncached top-5 by usage across the subtree, every tag pool — user request). `GET /api/directories/preview.gif?path=` serves the folder GIF from the local cache. `POST /api/directories` (create), `DELETE /api/directories?path=` (empty folders only, 400 `directory_not_empty`), `PUT /api/directories/favorite`, `GET /api/directories/favorites` — all delegating to `directory_ops.py`. `GET /api/directories/search?q=` — folder-name substring search, paginated, for the `path:` search scope. |
| [`backend/app/routers/files.py`](../backend/app/routers/files.py) | `GET /api/files` (filters: `directory`, `recursive`, `video_only`, `search`, `tags`, `tag_search`, `limit`/`offset`; entries carry `is_variant`/`is_original`/`variant_tags`/`ai_tags`), `GET /api/files/{id}`. Preview serving via `_preview_source_row()` (redirects a variant onto its original sibling's asset): `/preview` (metadata) and `/preview.jpg` read the JPEG collage from the source itself (`SourceAccess.exists()`/`read_bytes()`); `/preview.gif` is served from the local preview cache. `GET /{id}/tags` (assigned tags, `score > 0`), `POST/DELETE /{id}/tags[/{tag_id}]` (manual assign by `tag_id` or `display_name` → `score=100`/`manual`, ad-hoc pool), `POST /{id}/tags/user-defined` (same shape, but into the user-defined pool via `tags.assign_user_defined_tag()` — 404 `tag_not_found` for an unknown `tag_id`), `GET /{id}/similar`, `GET /{id}/media-info` (on-demand ffprobe, `null` fields when unprobeable), `DELETE /{id}` and `POST /{id}/move` (delegate to `file_ops.py`, error codes → HTTP statuses). |
| [`backend/app/routers/playback.py`](../backend/app/routers/playback.py) | `GET /api/files/{id}/playback` (mode + stream URL + direct path) and `GET /api/files/{id}/stream` — a manual Range-aware `StreamingResponse` over `access.open_range()`, one code path for both protocols; `_parse_range()` handles all three `bytes=` forms. |
| [`backend/app/routers/playback_settings.py`](../backend/app/routers/playback_settings.py) | `GET/PUT /api/playback-settings`. |
| [`backend/app/routers/conversion_profiles.py`](../backend/app/routers/conversion_profiles.py) | `GET/POST /api/conversion-profiles`, `PUT/DELETE /api/conversion-profiles/{id}`. |
| [`backend/app/routers/preview_layouts.py`](../backend/app/routers/preview_layouts.py) | `GET/POST /api/preview-layouts`, `PUT/DELETE /api/preview-layouts/{id}` (409 `preset_protected` for built-ins, 400 `invalid_layout`), stateless `POST /api/preview-layouts/preview` (live tile geometry for the editor). |
| [`backend/app/routers/preview_settings.py`](../backend/app/routers/preview_settings.py) | `GET/PUT /api/preview-settings` — PUT is a full replace, the frontend always sends the merged object. |
| [`backend/app/routers/tags.py`](../backend/app/routers/tags.py) | `GET /api/tags` (`query` prefix filter, `active_only`, `limit`, `category="ai"\|"user"` — scoped to one tag pool, default `"ai"`), `GET /api/tags/used` (`query`/`limit` — tags actually assigned to a file in this archive from *any* pool, usage-ordered; feeds every per-file add-tag autocomplete), `POST /api/tags` (409 on duplicate key; `is_ai_vocabulary`/`is_user_defined` select the pool; optional `color` hex string), `PUT/DELETE /api/tags/{id}`. Every tag response includes `color` — the stored value, or a deterministic hash-based fallback (`tags.resolve_tag_color()`) when never explicitly set, so a tag always has a usable, stable color everywhere it's rendered (user request). |
| [`backend/app/routers/tagging_settings.py`](../backend/app/routers/tagging_settings.py) | `GET/PUT /api/tagging-settings` (includes `request_timeout_seconds`, user request -- Tag Lab's direct provider call timeout, default 30); `POST /api/tagging-settings/preview` — stateless "what the model sees" demo: builds real tagging images (`app/tagging.py`) from a given file id with arbitrary (possibly unsaved) sample-frame-count/collage/resolution params, returned as base64 JPEG data URLs + pixel dimensions. |
| [`backend/app/routers/tag_lab.py`](../backend/app/routers/tag_lab.py) | `POST /files/{file_id}/tag-lab/prepare` (no body → `{images, prompt}` only, no provider call -- user request, lets the review UI show what's about to be sent before the slower `run` call below returns) and `POST /files/{file_id}/tag-lab/run` (`{provider_entry_id}` → `run_id` + images/prompt/raw response/`raw_full_response` (full provider JSON incl. usage, user request)/usage/ranked tags, nothing written except the run's feedback-snapshot row; images are resampled only if the file or tagging settings/vocabulary changed since the last call for that file, see `tag_lab._image_cache`) and `POST /files/{file_id}/tag-lab/apply` (`{provider_type, model_name, run_id?, tags}` → writes `file_tags`, records the apply-behavior KPI against `run_id` if given, returns the file's refreshed tag list) — the synchronous single-file, single-entry alternative to `POST /jobs/tag-file`'s background job. On a `tag_lab_failed` error, the HTTP error `detail.error` also carries `raw_response`/`raw_full_response` whenever the provider returned *something* before interpreting it failed (user request — the model's raw reply must stay inspectable even on a parse error; see `providers/base.py::ProviderError` and `tag_lab.TagLabError`). `POST /tag-lab/runs/{run_id}/feedback` (`{tag_id, display_name, vote: 1\|-1\|null}`) — like/dislike on one suggested tag from that run. |
| [`backend/app/routers/providers.py`](../backend/app/routers/providers.py) | `GET/POST /api/settings/provider-entries`, `PUT/DELETE .../{id}` (keys never echoed — only `has_api_key`/`key_suffix`), `POST .../reorder`, `POST .../models` (draft key) and `POST .../{id}/models` (stored key), `GET .../export` (JSON download **including plaintext keys** — deliberate, frontend warns first), `POST .../import` (reads the export shape back in, one new entry per item; unknown `provider_type` is skipped and counted, not fatal). `GET /api/settings/provider-usage` — the usage summary table. `GET /api/settings/model-pricing`, `PUT .../model-pricing` (`source='manual'`), `POST .../model-pricing/refresh-openrouter` (`source='openrouter_api'`, 400 `pricing_refresh_failed` on network error) — per-`(provider_type, model_name)` price editing. `GET /api/settings/model-ratings` — per-model like/dislike + apply-KPI stats. |
| [`backend/app/routers/jobs.py`](../backend/app/routers/jobs.py) | Job endpoints: `GET /api/jobs` (+ filters), `GET /{id}`, `GET /{id}/items`, `POST /{id}/cancel\|pause\|resume\|restart` (409 `job_not_pausable`/`job_not_resumable`), `DELETE /{id}`, `DELETE /api/jobs` (clear finished). Triggers: `rescan-directory`, `convert-directory`/`convert-file` (`variants` requires `mode: "test"`), `preview-directory`/`preview-file`, `tag-directory`/`tag-file` (400 `no_provider_configured`/`empty_tag_vocabulary`; the actual entry is resolved live by the worker), `cleanup-stale-records`, `optimize-database`. `GET/DELETE /api/jobs/batch-submissions[/{id}]` — declared *above* `GET /jobs/{id}` because a literal path segment must precede a same-method `/{id}` route or Starlette swallows it as an id. |
| [`backend/app/routers/logs.py`](../backend/app/routers/logs.py) | `GET /api/logs` (filters: `job_id`, `file_id`, `level`, `limit`) and `GET /api/logs/stream` — SSE polling `app_events` past the last-seen rowid every 0.5s. |
| [`backend/app/routers/backups.py`](../backend/app/routers/backups.py) | `GET /api/backups`, `POST /api/backups` (creates a `backup` job), `POST /api/backups/restore` (creates a `restore` job), `DELETE /api/backups/{id}` (synchronous). Source switching calls `app/backup.py` directly, not through here. |
| [`backend/app/routers/backup_settings.py`](../backend/app/routers/backup_settings.py) | `GET/PUT /api/backup-settings`. |
| [`backend/app/routers/interface_settings.py`](../backend/app/routers/interface_settings.py) | `GET/PUT /api/interface-settings` — the request model is built with `pydantic.create_model()` from `interface_settings.py`'s field/range constants, so validation and defaults stay in sync automatically. |
| [`backend/app/routers/performance_settings.py`](../backend/app/routers/performance_settings.py) | `GET/PUT /api/performance-settings`. |
