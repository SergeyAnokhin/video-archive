# Code Map — Backend Tests

Part of the [code map](code-map.md). **Update this file whenever test files are added, moved, or removed.** The test conventions these suites share (isolated DB/secrets, `make_video()`, the SMB fake, mocked providers) are summarized in [development.md](development.md#tests).

## `backend/tests/` — pytest

| Path | Role |
| --- | --- |
| [`backend/pytest.ini`](../backend/pytest.ini) | `pythonpath = .` so `tests/` can `import app.*` without path hacks. Run with `python -m pytest` from `backend/`. |
| [`backend/tests/conftest.py`](../backend/tests/conftest.py) | `isolated_secrets_file` fixture (autouse): points `app.secrets_store.SECRETS_PATH` at a per-test temp file, so tagging/provider tests that write API keys never touch the real `backend/secrets.env` (Stage 6 — this bit the repo once during development: a test run wrote real-looking keys into the tracked-ignored file before this fixture existed). `engine` fixture: isolated temp SQLite db per test (monkeypatches `app.db.DATABASE_PATH`/`_engine`), which also seeds the built-in preview presets/settings and tagging settings/provider rows via `init_db()`, so tests never touch the real `backend/video_archive.db`. `source` fixture: an active `local` source row over a temp directory. `make_files()`: creates N dummy (non-decodable) video files for job/scan tests. `make_video()`: encodes one tiny *real* video with ffmpeg (`testsrc` lavfi source) for tests that need ffprobe/ffmpeg to actually succeed, e.g. conversion, preview, and tagging frame extraction (`test_conversion.py`, `test_preview.py`, `test_tagging.py`); reuse this for any future stage that also shells out to ffmpeg. `FakeSMBFS` + `fake_smb`/`smb_source` fixtures ([Stage 7](./spec/roadmap.md#stage-7--smb-source-and-playback)): an in-memory fake of the tiny `smbclient` API surface `app/sources/smb_backend.py` calls (`register_session`/`scandir`/`stat`/`open_file`/`rename`/`remove`/`path.exists`/`path.isdir`), monkeypatched over the real `smbclient` module so SMB-source tests exercise the real `SMBBackend` code (UNC path building, retry-on-error) without a real SMB server — none is available in this environment/CI. |
| [`backend/tests/test_jobs.py`](../backend/tests/test_jobs.py) | Job queue state machine tests: cancel (queued instantly, running cooperatively via a real `JobWorker` thread with partial progress), restart/delete status gating, retention sweep, full `rescan` completion. |
| [`backend/tests/test_jobs_router.py`](../backend/tests/test_jobs_router.py) | HTTP-layer test for the `rescan-directory` → cancel/restart/delete lifecycle via `TestClient`. Deliberately does **not** exercise `GET /api/logs/stream` — `TestClient`'s sync ASGI bridge doesn't reliably stream an endless SSE generator and will hang; drive `stream_logs()` directly with `asyncio` instead if that endpoint ever needs a test. |
| [`backend/tests/test_conversion.py`](../backend/tests/test_conversion.py) | Conversion job tests against real ffmpeg/ffprobe (skipped automatically if neither is on `PATH`) and tiny synthetic videos from `conftest.make_video()`: profile CRUD/default-exclusivity, production replace, test-mode preserve (same and different source extension), invalid-output never touching the source (production and test mode), file-scope variant sweep never touching the source, directory-scope skip-processed, and recursive directory conversion (production and test) excluding `.original.`/`.variant-` artifacts. |
| [`backend/tests/test_conversion_router.py`](../backend/tests/test_conversion_router.py) | HTTP-layer validation tests: conversion-profile CRUD over `TestClient`, `convert-directory` profile/directory 404s, `convert-file` variants-require-test-mode 400 and file 404. Does not exercise real conversion (that's `test_conversion.py`'s job). |
| [`backend/tests/test_preview.py`](../backend/tests/test_preview.py) | Preview generation tests against real ffmpeg/ffprobe (skipped if unavailable): timeline sampling edge cases, grid-layout tile computation/validation (overlap/out-of-bounds/invalid-span rejection, full-coverage assertion), built-in preset protection, custom preset CRUD, collage rendering (file + folder preview JPEG output, aspect ratio, non-video rejection), and the `preview` job handler (file scope marks `has_preview_asset`, directory scope recursion with nested folder previews at every level, skip-processed rule, `.original.`/`.variant-` exclusion). |
| [`backend/tests/test_preview_router.py`](../backend/tests/test_preview_router.py) | HTTP-layer tests: preview-layout preset CRUD incl. built-in 409 protection and invalid-layout 400, the live `/preview-layouts/preview` geometry endpoint, `/preview-settings` GET/PUT incl. 422 on a bad `aspect_ratio`, `preview-directory`/`preview-file` job-trigger 404s, and `/files/{id}/preview(.jpg)` + `/directories/preview.jpg` image serving (404 when missing, 200 + `image/jpeg` when present). Does not exercise real preview generation (that's `test_preview.py`'s job). |
| [`backend/tests/test_similarity.py`](../backend/tests/test_similarity.py) | Similar video detection tests ([Stage 9](./spec/roadmap.md#stage-9--polish-and-optional-features), Specification §13) against real ffmpeg/ffprobe (skipped if unavailable): signature computation returns `None` for an unprobeable file, store/find-similar distinguishes a near-duplicate (`testsrc` lavfi pattern) from a visually distinct video (solid black) at a given Hamming-distance threshold, the `preview` job's file scope stores a signature as a side effect, and the `GET /api/files/{id}/similar` endpoint (404 for an unknown file, empty list before any signature exists, non-empty once signatures are stored). |
| [`backend/tests/test_tagging.py`](../backend/tests/test_tagging.py) | Tag vocabulary CRUD (normalize/dedupe/prefix-query/cascade-delete), `tagging_settings`/`provider_configs`/`secrets_store` singleton round-trips (incl. that a provider config never echoes the API key value back, only `has_api_key`), provider prompt-building/score-parsing (`app/providers/base.py`), frame/collage preparation against real ffmpeg (`app/tagging.py`, combine vs. per-frame), and the `tag` job handler (file + directory scope, skip-processed rule, test-artifact exclusion, top-N truncation, re-tagging replaces previous tags) with `app.providers.registry.score_tags_with_provider` monkeypatched to a deterministic stub — no real network calls in this suite; real-provider behavior was verified manually against OpenRouter instead (see `docs/spec/roadmap.md` Stage 6 "Done when"). |
| [`backend/tests/test_tagging_router.py`](../backend/tests/test_tagging_router.py) | HTTP-layer tests: tag CRUD + prefix autocomplete over `/api/tags`, `GET /api/files?tags=` (matches any of the given tag keys) and `GET /api/files/{id}/tags`, `/api/tagging-settings` GET/PUT, `/api/settings/providers` GET/PUT (asserts the API key never appears in any response body), and `tag-directory`/`tag-file` job-trigger validation (400 `no_provider_configured`, 400 `empty_tag_vocabulary`, 404s) — the provider call is stubbed here too since the job worker thread is live for the duration of these HTTP tests. |
| [`backend/tests/test_providers.py`](../backend/tests/test_providers.py) | Unit tests for each `app/providers/*.py` client's request construction and response parsing, with `httpx.post` monkeypatched (no real network call): correct URL/headers/payload shape per provider (including Mistral's bare-string vs. OpenRouter's `{"url": ...}` `image_url` shape, and FAL's whole-response-body score search), successful score parsing, and `ProviderError` on an HTTP error or a malformed response. Complements `test_tagging.py`, which stubs the whole `registry.score_tags_with_provider` call instead of exercising these request/response bodies. |
| [`backend/tests/test_tagging_batch.py`](../backend/tests/test_tagging_batch.py) | Batch tagging tests ([Stage 9](./spec/roadmap.md#stage-9--polish-and-optional-features), Specification §12.3): `submit_batch()` request construction/response parsing for `app/providers/gemini.py`/`mistral.py` with `httpx.post`/`httpx.get` monkeypatched (upload/create/poll/download sequence for Mistral, create/poll for Gemini's inlined mode; both happy-path and a batch-job-failure case), plus the `tag` job's directory-scope orchestration with `registry.score_tags_batch_with_provider`/`score_tags_with_provider` monkeypatched (no real ffmpeg dependency — `tagging.build_tagging_images` is stubbed too): all-files-succeed-via-batch, one-file-falls-back-per-file, and whole-batch-submission-raises-so-every-file-falls-back. |
| [`backend/tests/test_sources_smb.py`](../backend/tests/test_sources_smb.py) | SMB source tests (Stage 7) against the `fake_smb`/`smb_source` fixtures: `SMBBackend` UNC path building, `scandir`/`exists`, retry-on-connection-error, `local_copy()`/`commit_new_file()` download/upload + local-temp cleanup, `test_connection()`; end-to-end `scan_source_access()` discovery; and, skipped automatically without real ffmpeg/ffprobe, the `convert`/`preview`/`tag` job handlers running against an SMB source (production replace, test-mode preserve, file preview, file tagging with `registry.score_tags_with_provider` stubbed) — the SMB equivalents of `test_conversion.py`/`test_preview.py`/`test_tagging.py`. |
| [`backend/tests/test_source_router.py`](../backend/tests/test_source_router.py) | HTTP-layer tests for `/api/source*` (Stage 7): the pre-Stage-7 `local` connect/test-connection flow (regression) plus the `smb` flow (test-connection, connect with credential storage + scan, reconnect) against `fake_smb`, plus validation (`host_required`, `unsupported_protocol` for e.g. `webdav`); [Stage 8](./spec/roadmap.md#stage-8--backup-restore-maintenance-source-switching) adds a test that replacing a source (even with the same root path, as a reconnect does) wipes `jobs`/`job_items`/`app_events` in addition to `files`/`directories`, and that a backup made while connected is surfaced via `detected_backups` the next time that same disk is connected. |
| [`backend/tests/test_playback.py`](../backend/tests/test_playback.py) | Playback endpoint tests (Stage 7): `GET /api/files/{id}/playback` (mode + stream URL + direct path) for both `local` and `smb` sources; `GET /api/files/{id}/stream` Range-header handling (`_parse_range()` unit cases, 200 vs. 206 status/headers) for both protocols; `playback_settings` singleton round-trip. Byte-level correctness is checked directly against `access.open_range()` rather than through `StreamingResponse.body_iterator`, since the latter needs an async test runner (`pytest-asyncio`) that isn't a project dependency. |
| [`backend/tests/test_backup.py`](../backend/tests/test_backup.py) | Backup/restore/maintenance tests (Stage 8) calling `app/backup.py` and the `backup`/`restore`/`cleanup`/`optimize_db` job handlers directly (no HTTP layer, that's `test_backup_router.py`'s job): zip creation with manifest+data contents, empty-list-before-any-backup, retention trimming the oldest packages, delete, restoring a wiped library under a *new* source id (simulating the post-source-switch reconnect flow), rejecting a backup with a newer `schema_version`, rejecting a missing package, an `include_secrets` round-trip (secrets file cleared then restored from the package), the same create/restore flow against an `smb` source (`fake_smb`), and `cleanup`'s stale-vs-still-present record handling. |
| [`backend/tests/test_backup_router.py`](../backend/tests/test_backup_router.py) | HTTP-layer tests for `/api/backups*`/`/api/backup-settings`/the maintenance job triggers (Stage 8): 404 without a configured source; the full create → list → wipe → restore → delete lifecycle over `TestClient` (polling job status the same way `test_jobs_router.py`'s rescan test does, since backup/restore run through the real background `JobWorker`); `backup-settings` GET/PUT; `cleanup-stale-records`/`optimize-database` trigger + completion. |
| [`backend/tests/test_interface_settings.py`](../backend/tests/test_interface_settings.py) | Interface settings singleton tests ([Stage 9](./spec/roadmap.md#stage-9--polish-and-optional-features), Settings §9): service-level defaults/round-trip and the `GET/PUT /api/interface-settings` HTTP endpoint, same pattern as `playback_settings`'s tests. |
| [`backend/tests/test_status.py`](../backend/tests/test_status.py) | Derived directory status tests: `compute_directory_status()` aggregation (subtree prefix scoping incl. the `a`-vs-`ab` sibling-prefix case, `.original.`/`.variant-` and unsupported-file exclusion, empty-directory-counts-as-complete) and `GET /api/tree` (`include_status` payload, `depth` limiting, 404 on an unknown path). |
| [`backend/tests/test_pure_helpers.py`](../backend/tests/test_pure_helpers.py) | Unit tests for pure helpers with no external dependency: `media.is_test_artifact()`/`sibling_relative_path()`, `conversion.effective_max_dimension()`/`encode_variant_suffix()`/`build_ffmpeg_command()` (the exact argv handed to the external ffmpeg process — codec mapping, scale filter, audio drop/copy, extra encoder args — without running it), `preview_settings.effective_aspect_ratio()`, and `preview.select_frames_for_tiles()` with hand-built detection metadata (face > person > blur preference for enlarged tiles, row/column timeline flow) — no ffmpeg, no models, no database. |
