## `backend/tests/` — pytest

| Path | Role |
| --- | --- |
| [`backend/pytest.ini`](../backend/pytest.ini) | `pythonpath = .` so `tests/` can `import app.*` without path hacks. Run with `python -m pytest` from `backend/`. |
| [`backend/tests/conftest.py`](../backend/tests/conftest.py) | `isolated_secrets_file` fixture (autouse): points `app.secrets_store.SECRETS_PATH` at a per-test temp file, so tagging/provider tests that write API keys never touch the real `backend/secrets.env` (Stage 6 — this bit the repo once during development: a test run wrote real-looking keys into the tracked-ignored file before this fixture existed). `isolated_preview_cache` fixture (autouse, post-V1): same idea for `app.preview_cache.PREVIEW_CACHE_DIR` — points it at a per-test temp folder so preview-job/preview-router tests never write into the real `backend/preview_cache/`. `engine` fixture: isolated temp SQLite db per test (monkeypatches `app.db.DATABASE_PATH`/`_engine`), which also seeds the built-in preview presets/settings and tagging settings via `init_db()` (`provider_entries` starts empty — no seed rows, post-V1), so tests never touch the real `backend/video_archive.db`. `source` fixture: an active `local` source row over a temp directory. `make_files()`: creates N dummy (non-decodable) video files for job/scan tests. `make_video()`: encodes one tiny *real* video with ffmpeg (`testsrc` lavfi source, fixed `rate=5` regardless of the requested `duration`) for tests that need ffprobe/ffmpeg to actually succeed, e.g. conversion, preview, and tagging frame extraction (`test_conversion.py`, `test_preview.py`, `test_tagging.py`); reuse this for any future stage that also shells out to ffmpeg. Gotcha for GIF-output tests: sampling faster than that fixed 5fps (e.g. an 8fps clip burst) yields consecutive duplicate frames, and Pillow's `save(..., optimize=True)` can silently collapse those into fewer `n_frames` than were written — don't assert an exact `n_frames`/frame-count equality against a GIF built from this fixture; assert a lower bound or a duration-pattern check instead (see `test_preview.py`'s clip/crossfade tests). `FakeSMBFS` + `fake_smb`/`smb_source` fixtures ([Stage 7](./spec/roadmap.md#stage-7--smb-source-and-playback)): an in-memory fake of the tiny `smbclient` API surface `app/sources/smb_backend.py` calls (`register_session`/`scandir`/`stat`/`open_file`/`rename`/`remove`/`path.exists`/`path.isdir`), monkeypatched over the real `smbclient` module so SMB-source tests exercise the real `SMBBackend` code (UNC path building, retry-on-error) without a real SMB server — none is available in this environment/CI. |
| [`backend/tests/test_jobs.py`](../backend/tests/test_jobs.py) | Job queue state machine tests: cancel (queued instantly, running cooperatively via a real `JobWorker` thread with partial progress, or a paused job cancelled directly), restart/delete status gating, retention sweep, full `rescan` completion. Post-V1 (user request): pause/resume state-machine tests (queued-instant, finished/wrong-type conflicts, a real running-job pause-then-resume-to-completion round trip with slowed-down item creation for a reliable timing window); `test_cpu_and_network_job_types_are_partitioned`/`test_claim_next_queued_job_respects_job_types_filter` check the CPU/network lane split; `test_cpu_and_network_jobs_run_concurrently` proves the two lanes genuinely run at the same time by having two monkeypatched fake handlers block on a shared 2-party `threading.Barrier` — if the worker only ever ran one job at a time, the first handler would block forever waiting for a second job that can never get picked up, and the barrier's timeout would turn the job `failed` instead of `completed`. `test_get_job_and_list_jobs_report_failed_item_count` (post-V1, user request) checks `service.get_job()`/`.list_jobs()` both surface a live `failed_item_count` computed over `job_items`, not a stale/separately-tracked counter. `test_force_cancel_frees_the_lane_from_an_unresponsive_job` (post-V1, user request — root-caused from a `preview` job stuck indefinitely, unresponsive to Pause/Cancel) monkeypatches the `rescan` handler with one that blocks forever on a `threading.Event` to model a stuck job with no cooperative checkpoint, then asserts a second `cancel_job()` call force-finishes it (`job_force_cancelled` event) and that the lane immediately picks up the next queued job instead of waiting on the still-blocked handler thread. |
| [`backend/tests/test_jobs_router.py`](../backend/tests/test_jobs_router.py) | HTTP-layer test for the `rescan-directory` → cancel/restart/delete lifecycle via `TestClient`. Deliberately does **not** exercise `GET /api/logs/stream` — `TestClient`'s sync ASGI bridge doesn't reliably stream an endless SSE generator and will hang; drive `stream_logs()` directly with `asyncio` instead if that endpoint ever needs a test. Post-V1: `test_pause_and_resume_endpoints_over_http` checks 404s for an unknown job id and 409 conflicts for a finished job and for a non-pausable job type (`optimize_db`) — checked before status, so race-free against the live worker thread; a running-job pause/resume round trip isn't exercised here (timing-sensitive — see the direct, monkeypatch-controlled version in `test_jobs.py` instead). |
| [`backend/tests/test_conversion.py`](../backend/tests/test_conversion.py) | Conversion job tests against real ffmpeg/ffprobe (skipped automatically if neither is on `PATH`) and tiny synthetic videos from `conftest.make_video()`: profile CRUD/default-exclusivity, production replace, test-mode preserve (same and different source extension), invalid-output never touching the source (production and test mode), file-scope variant sweep never touching the source, directory-scope skip-processed, and recursive directory conversion (production and test) excluding `.original.`/`.variant-` artifacts. `test_probe_media_returns_none_instead_of_raising_on_null_stdout` (post-V1 regression test, monkeypatches `subprocess.run` — no real ffprobe call needed): `probe_media()` must return `None`, not raise, when ffprobe exits `0` but `stdout` comes back `None`. `test_probe_media_handles_non_ascii_path` (post-V1 regression test, real ffprobe call against a Cyrillic-named synthetic video from `make_video()`): `probe_media()` must successfully parse ffprobe's UTF-8 JSON output regardless of the OS console codepage. Post-V1 (`parallel_workers`, user request): `test_directory_scope_converts_all_files_across_multiple_batches`/`test_variant_sweep_produces_all_variants_across_multiple_batches` force `parallel_workers=2` against 5 candidates so the directory-scope loop and the variant sweep each flush through multiple `ThreadPoolExecutor` batches, asserting every file/variant still completes and is counted exactly once. Post-V1 (user request — per-stage progress visibility, mirroring `test_preview.py`'s equivalent): `test_convert_job_logs_per_stage_progress_events` asserts `job_item_progress` events for probing/encoding/validation land between `job_item_started` and `job_item_completed`. |
| [`backend/tests/test_conversion_router.py`](../backend/tests/test_conversion_router.py) | HTTP-layer validation tests: conversion-profile CRUD over `TestClient`, `convert-directory` profile/directory 404s, `convert-file` variants-require-test-mode 400 and file 404. Does not exercise real conversion (that's `test_conversion.py`'s job). |
| [`backend/tests/test_preview.py`](../backend/tests/test_preview.py) | Preview generation tests against real ffmpeg/ffprobe (skipped if unavailable): timeline sampling edge cases, grid-layout tile computation/validation (overlap/out-of-bounds/invalid-span rejection, full-coverage assertion), built-in preset protection, custom preset CRUD, collage rendering (file preview JPEG output, aspect ratio, non-video rejection), the companion GIF render (`gif_dest_path` produces an animated, width-capped GIF), `pick_representative_frames()` (single best-of-3 vs. multi-frame interior spread), `render_gif()`'s aspect-ratio cropping, and the `preview` job handler (file scope marks `has_preview_asset` and commits the GIF into `.video-archive/previews/` — not next to the video; directory scope recursion with nested animated `folder-preview.gif` at every level, skip-processed rule, `.original.`/`.variant-` exclusion). Post-V1 (`parallel_workers`, user request): `test_preview_job_directory_scope_generates_all_across_multiple_batches` forces `parallel_workers=2` against 5 candidates so the directory-scope loop flushes through multiple `ThreadPoolExecutor` batches, asserting every file still gets previewed and counted exactly once. Post-V1 (animated-preview source mode/transition, user request): `extract_clip_frames()` samples a multi-frame burst, `pick_representative_segments()` in `"frame"` vs `"clip"` mode, `render_gif()` with `segment_sizes`/`segment_seconds` holding a clip burst for the configured duration, and `render_gif(transition="crossfade")` inserting `CROSSFADE_STEPS` extra frames versus `"cut"` — plus the `preview_settings` singleton roundtrip now covers the three new animated-preview fields. Post-V1 (user request — a stuck preview job gave no way to tell which file it was on): `test_preview_job_items_and_events_identify_file_by_path` asserts `job_items.item_key` is the file's relative path (not left unset) and a `job_item_started` event is logged before `job_item_completed`, naming the file. Post-V1 (user request — per-stage progress visibility): `test_preview_job_logs_per_stage_progress_events` asserts `job_item_progress` events for probing/frame-extraction/collage-rendering land between `job_item_started` and `job_item_completed`. |
| [`backend/tests/test_preview_router.py`](../backend/tests/test_preview_router.py) | HTTP-layer tests: preview-layout preset CRUD incl. built-in 409 protection and invalid-layout 400, the live `/preview-layouts/preview` geometry endpoint, `/preview-settings` GET/PUT incl. 422 on a bad `aspect_ratio`, `preview-directory`/`preview-file` job-trigger 404s, and `/files/{id}/preview(.jpg\|.gif)` + `/directories/preview.gif` image serving (404 when missing, 200 + `image/jpeg`/`image/gif` when present).
