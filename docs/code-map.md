[Roadmap Stage 1](./spec/roadmap.md#stage-1--skeleton) through [Stage 9](./spec/roadmap.md#stage-9--polish-and-optional-features) are implemented — the full V1 scope from [Specification](./spec/specification.md), minus the explicitly out-of-scope-for-V1 WebDAV protocol (Specification §3): `frontend/` and `backend/` run together via the root `package.json`; the backend can connect a `local` source or an `smb` share, scan it, serve directory/file browsing endpoints, run background jobs (`rescan`, `convert`, `preview`, `tag`, `cleanup`, `optimize_db`, `backup`, `restore`) through a single sequential worker with live progress, an SSE log stream, and 24-hour retention, convert videos through ffmpeg with saved conversion profiles, safe production replacement, test-mode preservation, and file-scope variant comparison, generate preview collages (frame sampling + local face/person detection + PIL grid rendering) stored next to the videos as `<name>.jpg` and `folder-preview.jpg`, tag videos by sending a sampled-frame collage plus a user-defined tag vocabulary to a configured AI provider (OpenRouter, Gemini, FAL, or Mistral), storing the top-N scored tags, serve video playback through a Range-capable streaming proxy or a direct local/UNC path, and back up/restore local library metadata as zip packages in the source's `.video-archive/backups/` technical folder with configurable retention, alongside maintenance actions (full rescan, stale-record cleanup, database VACUUM/ANALYZE). All file access — scan, conversion, preview, tagging, playback, backup — goes through `app/sources/` (Stage 7, [§below](#backend--fastapi)) instead of raw `pathlib`, so the same code paths work for both source protocols; SMB credentials live in the same git-ignored secrets file as AI provider keys. The frontend renders a directory tree, library grid with real preview thumbnails, top-bar activity indicator, Jobs modal, Log Viewer, conversion-profile management, folder/file convert and preview dialogs (including variant comparison with promotion to a saved profile), a Preview Settings section with a construction-set grid editor and live layout preview, Tagging/AI-provider settings sections plus a compact tag-search box with prefix autocomplete in the library toolbar, a Source settings section covering both protocols (test-connection/connect/reconnect) with a destructive-replace warning and a post-connect backup-restore offer, a Playback Settings section, a Backup & Maintenance settings section (backup list/create/restore/delete, retention count, and the three maintenance actions), and a per-file "Play" action opening an embedded stream or a copyable direct path, on top of this.

Stage 9 ("Polish and Optional Features") adds a Playful theme preset ([Design System §2.2](./spec/design-system.md#22-playful)) alongside Strict, switchable from a top-bar icon-only toggle and persisted server-side through a new interface-settings singleton that now also owns the UI language (closing the pre-Stage-9 gap where language lived only in browser `localStorage`); a responsive/mobile refinement pass (an overflow menu for the library toolbar's secondary folder actions below 640px, restored 40×40 touch targets on the directory tree and breadcrumb at mobile widths, and a fix for file-card action buttons overlapping the name/size text at narrow card widths); optional similar-video detection (Specification §13) via a perceptual-hash (aHash) signature computed best-effort from each video's sampled preview frames, stored in the new `file_similarity_signatures` table, and surfaced through a per-file "Similar videos" action; and optional provider-side batch tagging (Specification §12.3) for the two providers with a real Batch API (Gemini, Mistral) — a directory-scope tag job with `batch_enabled` on now submits every pending file in one request instead of one call per file, falling back to the ordinary per-file path for anything the batch pass couldn't resolve. WebDAV (the other Stage 9 "optional" item) was deliberately not implemented: Specification §3 lists it as out of scope for V1 outright, unlike the other optional items, which are in-spec but secondary.
