[Roadmap Stage 1](./spec/roadmap.md#stage-1--skeleton) through [Stage 9](./spec/roadmap.md#stage-9--polish-and-optional-features) are implemented — the full V1 scope from [Specification](./spec/specification.md), minus the explicitly out-of-scope-for-V1 WebDAV protocol (Specification §3): `frontend/` and `backend/` run together via the root `package.json`; the backend can connect a `local` source or an `smb` share, scan it, serve directory/file browsing endpoints, run background jobs (`rescan`, `convert`, `preview`, `tag`, `cleanup`, `optimize_db`, `backup`, `restore`) through a worker with live progress, an SSE log stream, and 24-hour retention (post-V1: a two-lane worker with pause/resume, see below), convert videos through ffmpeg with saved conversion profiles, safe production replacement, test-mode preservation, and file-scope variant comparison, generate preview collages (frame sampling + local face/person detection + PIL grid rendering) stored next to the videos as `<name>.jpg` (plus a companion animated GIF), and animated `folder-preview.gif` loops cycling frames diversely sampled across a folder's videos/subfolders, tag videos by sending a sampled-frame collage plus a user-defined tag vocabulary to a configured AI provider (OpenRouter, Gemini, FAL, or Mistral), storing the top-N scored tags, serve video playback through a Range-capable streaming proxy or a direct local/UNC path, and back up/restore local library metadata as zip packages in the source's `.video-archive/backups/` technical folder with configurable retention, alongside maintenance actions (full rescan, stale-record cleanup, database VACUUM/ANALYZE). All file access — scan, conversion, preview, tagging, playback, backup — goes through `app/sources/` (Stage 7, [§below](#backend--fastapi)) instead of raw `pathlib`, so the same code paths work for both source protocols; SMB credentials live in the same git-ignored secrets file as AI provider keys. The frontend renders a directory tree, library grid with real preview thumbnails, top-bar activity indicator, Jobs modal, Log Viewer, conversion-profile management, folder/file convert and preview dialogs (including variant comparison with promotion to a saved profile), a Preview Settings section with a construction-set grid editor and live layout preview, Tagging/AI-provider settings sections plus a compact tag-search box with prefix autocomplete in the library toolbar, a Source settings section covering both protocols (test-connection/connect/reconnect) with a destructive-replace warning and a post-connect backup-restore offer, a Playback Settings section, a Backup & Maintenance settings section (backup list/create/restore/delete, retention count, and the three maintenance actions), and a per-file "Play" action opening an embedded stream or a copyable direct path, on top of this.

Post-V1, the library UI was simplified per direct user feedback: search moved into the top bar, the directory tree is collapsed by default at every width (menu-toggle only), file cards were cut down to click-to-play plus a single "i" info-panel button (replacing five per-card icons), playback is a minimal full-viewport overlay, the grid only ever shows folders/videos, folder refetches on job completion, and a third theme preset (Casino) was added — see `code-map-frontend.md` for the file-level detail. Also post-V1 (user request, 2026-07, ported from a Claude Design mockup): five more theme presets were added (Neon Night, Toxic Arcade, Cyber Violet, Vivid Glam, Mono Ice — 8 total), each theme picker option now shows a two-dot accent-pair swatch, and the theme system gained a second accent CSS variable (`--color-accent-2`) for two-tone effects. Also post-V1 (user request): the job worker went from one strictly-sequential lane to two concurrent lanes — one CPU-bound (`rescan`/`convert`/`preview`/`cleanup`/`optimize_db`/`backup`/`restore`), one network-bound (`tag`, since it calls an external AI provider API instead of competing for local ffmpeg/CPU) — plus a `paused` job status with pause/resume endpoints so a running job can free its lane for another queued one; the Jobs modal was widened and its cards laid out in a responsive grid (`code-map-frontend.md`/`code-map-backend.md` have the file-level detail). Also post-V1 (user request): within one `convert`/`preview` job, a configurable number of files (or, for a single file, that file's own independent per-item work — variant encodes, preview frame extractions) now run concurrently instead of strictly one at a time, via a new `parallel_workers` performance settings singleton (Settings → Performance) — see `app/performance_settings.py` and the `jobs/convert.py`/`jobs/preview.py` entries in `code-map-backend.md`.

Stage 9 ("Polish and Optional Features") adds a Playful theme preset ([Design System §2.2](./spec/design-system.md#22-playful)) alongside Strict, switchable from a top-bar icon-only toggle and persisted server-side through a new interface-settings singleton that now also owns the UI language (closing the pre-Stage-9 gap where language lived only in browser `localStorage`); a responsive/mobile refinement pass (an overflow menu for the library toolbar's secondary folder actions below 640px, restored 40×40 touch targets on the directory tree and breadcrumb at mobile widths, and a fix for file-card action buttons overlapping the name/size text at narrow card widths); optional similar-video detection (Specification §13) via a perceptual-hash (aHash) signature computed best-effort from each video's sampled preview frames, stored in the new `file_similarity_signatures` table, and surfaced through a per-file "Similar videos" action; and optional provider-side batch tagging (Specification §12.3) for the two providers with a real Batch API (Gemini, Mistral) — a directory-scope tag job with `batch_enabled` on now submits every pending file in one request instead of one call per file, falling back to the ordinary per-file path for anything the batch pass couldn't resolve. WebDAV (the other Stage 9 "optional" item) was deliberately not implemented: Specification §3 lists it as out of scope for V1 outright, unlike the other optional items, which are in-spec but secondary.
