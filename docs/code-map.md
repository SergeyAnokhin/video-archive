# Code Map

Living map of the implementation files in this repository. **This file must be updated whenever code files are added, moved, or removed.**

[Roadmap Stage 1](./roadmap.md#stage-1--skeleton), [Stage 2](./roadmap.md#stage-2--local-source-scan-browsing), and [Stage 3](./roadmap.md#stage-3--job-infrastructure) are implemented: `frontend/` and `backend/` run together via the root `package.json`; the backend can connect a `local` source, scan it, serve directory/file browsing endpoints, and run background jobs (currently `rescan`) through a single sequential worker with live progress, an SSE log stream, and 24-hour retention. The frontend renders a directory tree, library grid, top-bar activity indicator, Jobs modal, and Log Viewer on top of this. Later stages will add conversion, previews, tagging, and playback.

## `backend/` — FastAPI

| Path | Role |
| --- | --- |
| [`backend/package.json`](../backend/package.json) | Wraps the Python startup (`pip install` + `uvicorn --reload`) so the root `npm run dev` can start it. |
| [`backend/requirements.txt`](../backend/requirements.txt) | Python dependencies: FastAPI, Uvicorn, SQLAlchemy, sse-starlette, python-dotenv. |
| [`backend/app/main.py`](../backend/app/main.py) | FastAPI app; on startup initializes the database, checks ffmpeg availability once, and starts the background `JobWorker` (stopped again on shutdown). Wires up the `health`, `app_info`, `source`, `tree`, `directories`, `files`, `jobs`, and `logs` routers. |
| [`backend/app/config.py`](../backend/app/config.py) | App version constant and the SQLite database path. |
| [`backend/app/db.py`](../backend/app/db.py) | SQLite initialization via SQLAlchemy; schema versioning through an ordered `MIGRATIONS` map and a single-row `schema_meta` table. Migration 2 creates `sources`, `directories`, and `files` ([Data Model §1-3](./data-model.md)); migration 3 creates `jobs`, `job_items`, and `app_events` ([Data Model §6-7, §11](./data-model.md)). `get_engine()` sets `check_same_thread=False` plus `PRAGMA journal_mode=WAL`/`busy_timeout`, since the job worker thread and request-handling threads now share one SQLite connection pool. Later stages append further migrations (conversion profiles, tags, etc.) instead of editing these. |
| [`backend/app/ffmpeg.py`](../backend/app/ffmpeg.py) | Locates `ffmpeg` on `PATH` and reads its version. |
| [`backend/app/media.py`](../backend/app/media.py) | Supported video extension list, the `.video-archive` technical folder name, and the fixed `folder-preview.jpg` name ([Tech Stack](./tech-stack.md#supported-video-extensions), [Specification §5.3](./specification.md#53-technical-folder), [§9.5](./specification.md#95-preview-storage)). |
| [`backend/app/scan.py`](../backend/app/scan.py) | `discover_filesystem()` walks a root (or a subtree of it) and returns the directories/files found; `upsert_directory()`/`upsert_file()` insert-or-update one row each. `scan_source()` composes these for a whole-source batch scan (unchanged behavior from Stage 2). The Stage 3 `rescan` job (`app/jobs/rescan.py`) reuses the same three functions to refresh one directory subtree file-by-file instead of in one batch ([Specification §6.1](./specification.md#61-scan)). |
| [`backend/app/status.py`](../backend/app/status.py) | `compute_directory_status()`: derives per-subtree conversion/preview completeness and counts from `files` rows, never persisted ([Specification §14](./specification.md#14-file-and-directory-state-model)). |
| [`backend/app/source_access.py`](../backend/app/source_access.py) | `get_active_source_or_404()` helper shared by the browsing routers. |
| [`backend/app/jobs/service.py`](../backend/app/jobs/service.py) | Job/job-item CRUD and the `queued → running → completed\|failed\|cancelled` state machine ([Job Model](./job-model.md)); `log_event()` writes `app_events` rows; an in-memory cancel-request registry lets `cancel_job()` flag a *running* job cooperatively (a *queued* job is cancelled immediately, no worker involved yet); `run_retention_sweep()` deletes finished jobs/items/events older than 24h. Every function opens its own short transaction so it's safe to call from request threads and the worker thread alike. |
| [`backend/app/jobs/worker.py`](../backend/app/jobs/worker.py) | `JobWorker`: the single sequential worker ([Job Model "Concurrency Model"](./job-model.md#concurrency-model)) — a daemon thread that polls for the oldest `queued` job, runs its handler (a `job_type -> handler` dispatch table, currently just `rescan`), finishes the job, and periodically runs the retention sweep. Started/stopped from `main.py`'s lifespan. |
| [`backend/app/jobs/rescan.py`](../backend/app/jobs/rescan.py) | `run_rescan_job()`: the `rescan` job handler. Walks the target subtree via `discover_filesystem()`, batch-upserts directories, then processes files one at a time as individual `job_items` (own transaction + `app_events` per file) so progress is visible live and cancellation is checked between files; removes stale rows scoped to the subtree afterward. |
| [`backend/app/routers/health.py`](../backend/app/routers/health.py) | `GET /api/health`. |
| [`backend/app/routers/app_info.py`](../backend/app/routers/app_info.py) | `GET /api/app/info`: app version, active source summary (`null` if none configured), database status, queue status (current queued/running job summary from `jobs.service.get_current_job_summary()`, `null` when idle), ffmpeg availability. |
| [`backend/app/routers/source.py`](../backend/app/routers/source.py) | `GET /api/source`, `PUT /api/source` (accepts `protocol: "local"` only for now; replacing wipes `directories`/`files` and runs a synchronous scan), `POST /api/source/test-connection` ([Specification §5](./specification.md#5-source-model), [Settings §1](./settings-spec.md#1-source-connection-settings)). SMB/WebDAV are rejected with a 400 until [Stage 7](./roadmap.md#stage-7--smb-source-and-playback). The connect/replace scan stays synchronous here (unchanged from Stage 2); only `rescan-directory` runs through the Stage 3 job queue so far. |
| [`backend/app/routers/tree.py`](../backend/app/routers/tree.py) | `GET /api/tree`: recursive directory tree from a given `path`, with optional `depth` limit and `include_status` indicators. |
| [`backend/app/routers/directories.py`](../backend/app/routers/directories.py) | `GET /api/directories/children`: immediate subfolders + files for one directory, with optional `include_status`. |
| [`backend/app/routers/files.py`](../backend/app/routers/files.py) | `GET /api/files` (filters: `directory`, `recursive`, `video_only`, `search`, `limit`/`offset`; tag filtering arrives with tagging in [Stage 6](./roadmap.md#stage-6--tagging-and-search)) and `GET /api/files/{file_id}`. |
| [`backend/app/routers/jobs.py`](../backend/app/routers/jobs.py) | Job endpoints ([API §6-7](./api-spec.md#6-jobs)): `GET /api/jobs` (filters: `status`, `job_type`, `limit`/`offset`), `GET /api/jobs/{id}`, `GET /api/jobs/{id}/items`, `POST /api/jobs/{id}/cancel`, `POST /api/jobs/{id}/restart`, `DELETE /api/jobs/{id}`, `DELETE /api/jobs` (clear all finished), and `POST /api/jobs/rescan-directory` (the one job-creating trigger wired up so far; `scan-source`/`cleanup-stale-records`/`optimize-database` are declared in the API spec but arrive with their own stages). |
| [`backend/app/routers/logs.py`](../backend/app/routers/logs.py) | `GET /api/logs` (filters: `job_id`, `file_id`, `level`, `limit`) and `GET /api/logs/stream` — an SSE endpoint (`sse-starlette`) that polls `app_events` for rows past the last-seen `rowid` every 0.5s ([API §12](./api-spec.md#12-logs-and-events)). |

Not yet created (see [Tech Stack](./tech-stack.md#repository-layout-target)): `backend/secrets.env` (arrives with SMB/provider credentials), detection model files (Stage 5), the remaining SQLite entity tables (`conversion_profiles`, `preview_layout_presets`, `tag_catalog`, `file_tags`, `file_similarity_signatures` — introduced incrementally per stage).
