# Code Map

Living map of the implementation files in this repository. **This file must be updated whenever code files are added, moved, or removed.**

[Roadmap Stage 1](./roadmap.md#stage-1--skeleton) through [Stage 4](./roadmap.md#stage-4--conversion) are implemented: `frontend/` and `backend/` run together via the root `package.json`; the backend can connect a `local` source, scan it, serve directory/file browsing endpoints, run background jobs (`rescan`, `convert`) through a single sequential worker with live progress, an SSE log stream, and 24-hour retention, and convert videos through ffmpeg with saved conversion profiles, safe production replacement, test-mode preservation, and file-scope variant comparison. The frontend renders a directory tree, library grid, top-bar activity indicator, Jobs modal, Log Viewer, conversion-profile management, and folder/file convert dialogs (including variant comparison with promotion to a saved profile) on top of this. Later stages will add previews, tagging, and playback.

| Path | Role |

| [`backend/package.json`](../backend/package.json) | Wraps the Python startup (`pip install` + `uvicorn --reload`) so the root `npm run dev` can start it. |
| [`backend/requirements.txt`](../backend/requirements.txt) | Python dependencies: FastAPI, Uvicorn, SQLAlchemy, sse-starlette, python-dotenv, pytest + httpx (test-only, no separate dev-requirements file). |
| [`backend/pytest.ini`](../backend/pytest.ini) | `pythonpath = .` so `tests/` can `import app.*` without path hacks. Run with `python -m pytest` from `backend/`. |
| [`backend/tests/conftest.py`](../backend/tests/conftest.py) | `engine` fixture: isolated temp SQLite db per test (monkeypatches `app.db.DATABASE_PATH`/`_engine`) so tests never touch the real `backend/video_archive.db`. `source` fixture: an active `local` source row over a temp directory. `make_files()`: creates N dummy (non-decodable) video files for job/scan tests. `make_video()`: encodes one tiny *real* video with ffmpeg (`testsrc` lavfi source) for tests that need ffprobe/ffmpeg to actually succeed, e.g. conversion; reuse this for any future stage that also shells out to ffmpeg (previews in [Stage 5](./roadmap.md#stage-5--preview-generation)). |
| [`backend/tests/test_jobs.py`](../backend/tests/test_jobs.py) | Job queue state machine tests: cancel (queued instantly, running cooperatively via a real `JobWorker` thread with partial progress), restart/delete status gating, retention sweep, full `rescan` completion. |
| [`backend/tests/test_jobs_router.py`](../backend/tests/test_jobs_router.py) | HTTP-layer test for the `rescan-directory` → cancel/restart/delete lifecycle via `TestClient`. Deliberately does **not** exercise `GET /api/logs/stream` — `TestClient`'s sync ASGI bridge doesn't reliably stream an endless SSE generator and will hang; drive `stream_logs()` directly with `asyncio` instead if that endpoint ever needs a test. |
| [`backend/tests/test_conversion.py`](../backend/tests/test_conversion.py) | Conversion job tests against real ffmpeg/ffprobe (skipped automatically if neither is on `PATH`) and tiny synthetic videos from `conftest.make_video()`: profile CRUD/default-exclusivity, production replace, test-mode preserve (same and different source extension), invalid-output never touching the source (production and test mode), file-scope variant sweep never touching the source, directory-scope skip-processed, and recursive directory conversion (production and test) excluding `.original.`/`.variant-` artifacts. |
| [`backend/tests/test_conversion_router.py`](../backend/tests/test_conversion_router.py) | HTTP-layer validation tests: conversion-profile CRUD over `TestClient`, `convert-directory` profile/directory 404s, `convert-file` variants-require-test-mode 400 and file 404. Does not exercise real conversion (that's `test_conversion.py`'s job). |
| [`backend/app/main.py`](../backend/app/main.py) | FastAPI app; on startup initializes the database, checks ffmpeg availability once, and starts the background `JobWorker` (stopped again on shutdown). Wires up the `health`, `app_info`, `source`, `tree`, `directories`, `files`, `conversion_profiles`, `jobs`, and `logs` routers. |
| [`backend/app/config.py`](../backend/app/config.py) | App version constant and the SQLite database path. |
| [`backend/app/db.py`](../backend/app/db.py) | SQLite initialization via SQLAlchemy; schema versioning through an ordered `MIGRATIONS` map and a single-row `schema_meta` table. Migration 2 creates `sources`, `directories`, and `files` ([Data Model §1-3](./data-model.md)); migration 3 creates `jobs`, `job_items`, and `app_events` ([Data Model §6-7, §11](./data-model.md)); migration 4 creates `conversion_profiles` ([Data Model §4](./data-model.md#4-conversion_profiles)). `get_engine()` sets `check_same_thread=False` plus `PRAGMA journal_mode=WAL`/`busy_timeout`, since the job worker thread and request-handling threads now share one SQLite connection pool. Later stages append further migrations (preview presets, tags, etc.) instead of editing these. |
| [`backend/app/ffmpeg.py`](../backend/app/ffmpeg.py) | Locates `ffmpeg` on `PATH` and reads its version (startup availability check only; actual encode/probe commands live in `app/conversion.py`). |
| [`backend/app/conversion.py`](../backend/app/conversion.py) | ffmpeg/ffprobe building blocks used by the `convert` job ([Specification §7-8](./specification.md#7-conversion-profiles)): `probe_media()` (ffprobe JSON → format/video-stream summary), `effective_max_dimension()` (resize only when the source exceeds the configured limit), `build_ffmpeg_command()` (codec/CRF/scale-filter/audio-drop args from a profile), `run_ffmpeg()`, `validate_converted_output()` (existence, non-zero size, ffprobe-recognized, expected container/codec — Specification §8.1's lightweight validation pass), and `encode_variant_suffix()` for `<basename>.variant-<params>.mp4` naming. |
| [`backend/app/conversion_profiles.py`](../backend/app/conversion_profiles.py) | Conversion profile CRUD ([Data Model §4](./data-model.md#4-conversion_profiles)): `list/get/create/update/delete_profile()`. Setting `is_default` on one profile clears it on all others; deletion is unconditional (profiles have no `is_builtin`/protected concept, unlike preview layout presets). |
| [`backend/app/media.py`](../backend/app/media.py) | Supported video extension list, the `.video-archive` technical folder name, the fixed `folder-preview.jpg` name, and `is_test_artifact()` (detects `.original.`/`.variant-` naming markers so bulk convert/preview/tag jobs can exclude preserved originals and variant outputs — [Specification §8.2-8.3](./specification.md#82-test-mode)). |
| [`backend/app/scan.py`](../backend/app/scan.py) | `discover_filesystem()` walks a root (or a subtree of it) and returns the directories/files found; `upsert_directory()`/`upsert_file()` insert-or-update one row each. `scan_source()` composes these for a whole-source batch scan (unchanged behavior from Stage 2). The Stage 3 `rescan` job (`app/jobs/rescan.py`) reuses the same three functions to refresh one directory subtree file-by-file instead of in one batch ([Specification §6.1](./specification.md#61-scan)). |
| [`backend/app/status.py`](../backend/app/status.py) | `compute_directory_status()`: derives per-subtree conversion/preview completeness and counts from `files` rows, excluding `.original.`/`.variant-` test artifacts so leftover comparison files don't keep a folder's indicator permanently "incomplete"; never persisted ([Specification §14](./specification.md#14-file-and-directory-state-model)). |
| [`backend/app/source_access.py`](../backend/app/source_access.py) | `get_active_source_or_404()` helper shared by the browsing routers. |
| [`backend/app/jobs/service.py`](../backend/app/jobs/service.py) | Job/job-item CRUD and the `queued → running → completed\|failed\|cancelled` state machine ([Job Model](./job-model.md)); `log_event()` writes `app_events` rows; an in-memory cancel-request registry lets `cancel_job()` flag a *running* job cooperatively (a *queued* job is cancelled immediately, no worker involved yet); `skip_job_item()` marks a job item `skipped` (the skip-processed rule); `run_retention_sweep()` deletes finished jobs/items/events older than 24h. Every function opens its own short transaction so it's safe to call from request threads and the worker thread alike. |
| [`backend/app/jobs/worker.py`](../backend/app/jobs/worker.py) | `JobWorker`: the single sequential worker ([Job Model "Concurrency Model"](./job-model.md#concurrency-model)) — a daemon thread that polls for the oldest `queued` job, runs its handler (a `job_type -> handler` dispatch table: `rescan`, `convert`), finishes the job, and periodically runs the retention sweep. Started/stopped from `main.py`'s lifespan. |
| [`backend/app/jobs/rescan.py`](../backend/app/jobs/rescan.py) | `run_rescan_job()`: the `rescan` job handler. Walks the target subtree via `discover_filesystem()`, batch-upserts directories, then processes files one at a time as individual `job_items` (own transaction + `app_events` per file) so progress is visible live and cancellation is checked between files; removes stale rows scoped to the subtree afterward. |
| [`backend/app/jobs/convert.py`](../backend/app/jobs/convert.py) | `run_convert_job()`: the `convert` job handler ([Specification §6.2, §8](./specification.md#8-safe-file-replacement-and-test-mode)), dispatching on job scope: directory scope converts every supported video recursively (skip-processed rule, always excluding `is_test_artifact()` names); file scope either runs one production/test conversion or, when `parameters.variants` is set, a variant-comparison sweep. Production mode (`_replace_production`) encodes to a temp file, validates, then replaces the source only on success (temp is deleted and the source left untouched on failure). Test mode (`_replace_test_mode`) renames the original to `<basename>.original.<ext>` and writes the converted output as a new `files` row only after validation succeeds; on failure the source is never renamed. Variants (`_create_variant`) never touch the source file at all, successful or not. |
| [`backend/app/routers/health.py`](../backend/app/routers/health.py) | `GET /api/health`. |
| [`backend/app/routers/app_info.py`](../backend/app/routers/app_info.py) | `GET /api/app/info`: app version, active source summary (`null` if none configured), database status, queue status (current queued/running job summary from `jobs.service.get_current_job_summary()`, `null` when idle), ffmpeg availability. |
| [`backend/app/routers/source.py`](../backend/app/routers/source.py) | `GET /api/source`, `PUT /api/source` (accepts `protocol: "local"` only for now; replacing wipes `directories`/`files` and runs a synchronous scan), `POST /api/source/test-connection` ([Specification §5](./specification.md#5-source-model), [Settings §1](./settings-spec.md#1-source-connection-settings)). SMB/WebDAV are rejected with a 400 until [Stage 7](./roadmap.md#stage-7--smb-source-and-playback). The connect/replace scan stays synchronous here (unchanged from Stage 2); only `rescan-directory` and the `convert-*` triggers run through the job queue so far. |
| [`backend/app/routers/tree.py`](../backend/app/routers/tree.py) | `GET /api/tree`: recursive directory tree from a given `path`, with optional `depth` limit and `include_status` indicators. |
| [`backend/app/routers/directories.py`](../backend/app/routers/directories.py) | `GET /api/directories/children`: immediate subfolders + files for one directory, with optional `include_status`. |
| [`backend/app/routers/files.py`](../backend/app/routers/files.py) | `GET /api/files` (filters: `directory`, `recursive`, `video_only`, `search`, `limit`/`offset`; tag filtering arrives with tagging in [Stage 6](./roadmap.md#stage-6--tagging-and-search)) and `GET /api/files/{file_id}`. |
| [`backend/app/routers/conversion_profiles.py`](../backend/app/routers/conversion_profiles.py) | Conversion profile endpoints ([API §4](./api-spec.md#4-conversion-profiles)): `GET/POST /api/conversion-profiles`, `PUT/DELETE /api/conversion-profiles/{id}`. |
| [`backend/app/routers/jobs.py`](../backend/app/routers/jobs.py) | Job endpoints ([API §6-8](./api-spec.md#6-jobs)): `GET /api/jobs` (filters: `status`, `job_type`, `limit`/`offset`), `GET /api/jobs/{id}`, `GET /api/jobs/{id}/items`, `POST /api/jobs/{id}/cancel`, `POST /api/jobs/{id}/restart`, `DELETE /api/jobs/{id}`, `DELETE /api/jobs` (clear all finished), `POST /api/jobs/rescan-directory`, and the Stage 4 conversion triggers `POST /api/jobs/convert-directory` and `POST /api/jobs/convert-file` (the latter accepts an optional `variants` list, rejected with 400 unless `mode: "test"`). `scan-source`/`cleanup-stale-records`/`optimize-database` are declared in the API spec but arrive with their own stages. |
| [`backend/app/routers/logs.py`](../backend/app/routers/logs.py) | `GET /api/logs` (filters: `job_id`, `file_id`, `level`, `limit`) and `GET /api/logs/stream` — an SSE endpoint (`sse-starlette`) that polls `app_events` for rows past the last-seen `rowid` every 0.5s ([API §12](./api-spec.md#12-logs-and-events)). |

Not yet created (see [Tech Stack](./tech-stack.md#repository-layout-target)): `backend/secrets.env` (arrives with SMB/provider credentials), detection model files (Stage 5), the remaining SQLite entity tables (`preview_layout_presets`, `tag_catalog`, `file_tags`, `file_similarity_signatures` — introduced incrementally per stage).

Known gap (pre-existing, not introduced this stage): HTTPException error bodies across all routers are nested under FastAPI's default `{"detail": {"error": {...}}}` rather than the top-level `{"error": {...}}` shape shown in [API Specification's Error Model](./api-spec.md#error-model); no custom exception handler is registered. Worth a dedicated fix if the frontend ever needs to branch on error codes broadly.
