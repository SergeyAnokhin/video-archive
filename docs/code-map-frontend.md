| [`frontend/src/components/TopBar.tsx`](../frontend/src/components/TopBar.tsx) (+ `.css`) | Top bar, redesigned to consolidate global controls in one row (user request): menu toggle (opens the directory-tree pane at every breakpoint, not just mobile/tablet — the tree is collapsed by default everywhere now, see `AppLayout.tsx`), app title, a centered `LibrarySearchBox` (moved here from `LibraryView.tsx` so search lives in the header rather than the per-folder toolbar), then a right-hand icon-button group: an activity indicator (only rendered while a job is queued/running, hover tooltip via `jobs.indicatorTooltip`, spins with a functional CSS animation), a persistent Jobs button, preview-visibility toggle (eye icon), a theme toggle (single icon-only button cycling `strict → playful → casino → strict` via `useInterfaceSettings()`, icon and label follow the *next* theme in the cycle), and the Settings button. `activeSearch` state itself lives in `AppLayout.tsx` (passed down as `onSearch`/`onClearSearch`) since both `TopBar` (renders the box) and `LibraryView` (renders results) need it. Both Jobs-related buttons open `JobsModal`. Language selection is not in the top bar — see `SettingsModal.tsx`. |
| [`frontend/src/components/LibrarySearchBox.tsx`](../frontend/src/components/LibrarySearchBox.tsx) (+ `.css`) | Tag/name search box, extracted from `LibraryView.tsx` so `TopBar.tsx` can render it too: filters `useTags()`'s already-loaded vocabulary by prefix as the user types (no per-keystroke request) and, on picking a suggestion or pressing Enter, calls `onSearch` with an `ActiveSearch` (`{ kind: 'tag' \| 'name', label, value }`) that the parent (`AppLayout.tsx`) turns into `LibraryView`'s flat search-results view. |
| [`frontend/src/components/SettingsModal.tsx`](../frontend/src/components/SettingsModal.tsx) (+ `.css`) | Thin settings surface opened from the top bar's Settings button: modal chrome (header, close button, Escape-to-close) rendering one section component per settings group, in order `SourceSection`, `ConversionProfilesSection`, `PreviewSettingsSection`, `PlaybackSettingsSection`, `TaggingSettingsSection`, `ProviderSettingsSection`, `BackupMaintenanceSection`, `InterfaceSection`. Becomes a full-screen sheet on mobile ([Design System §5](./spec/design-system.md#5-responsive-breakpoints)). A placeholder for the fuller icon-rail Settings screen described in [Design System §1](./spec/design-system.md#1-reference-inspiration); later stages add further section components here rather than growing this file. All sections share `SettingsModal.css`. |
| [`frontend/src/components/SourceSection.tsx`](../frontend/src/components/SourceSection.tsx) | Source settings group: a protocol selector (`local`/`smb`) toggling between a local-path form and an SMB form (host/port/share-path/username/password), test-connection, connect/replace with a destructive-replace confirmation step per [Specification §5.2](./spec/specification.md#52-source-switching), a Reconnect button shown only for an active `smb` source ([Stage 7](./spec/roadmap.md#stage-7--smb-source-and-playback)) posting `POST /api/source/reconnect`, and ([Stage 8](./spec/roadmap.md#stage-8--backup-restore-maintenance-source-switching)) a post-connect backup-restore offer: `PUT /api/source`'s response includes `detected_backups` (backups found in the newly connected source's technical folder), rendered as a list with a "Restore" button per entry that posts `POST /api/backups/restore` and refreshes `JobsContext`. |
| [`frontend/src/components/PlaybackSettingsSection.tsx`](../frontend/src/components/PlaybackSettingsSection.tsx) | Playback settings group ([Settings §4](./spec/settings-spec.md#4-playback-settings), [UI Screens §8](./spec/ui-screens.md#8-playback-settings-screen)): a single `stream`/`direct_link` mode selector persisted via `GET/PUT /api/playback-settings`; both strategies stay available from the library regardless of this default. |
| [`frontend/src/components/ConversionProfilesSection.tsx`](../frontend/src/components/ConversionProfilesSection.tsx) | Conversion Profiles settings group ([UI Screens §6](./spec/ui-screens.md#6-conversion-profiles-screen)): create/edit/duplicate/delete/mark-default, backed by `useConversionProfiles()` and the `/api/conversion-profiles` endpoints; includes the internal `ConversionProfileForm` used for add/edit. |
| [`frontend/src/components/PreviewSettingsSection.tsx`](../frontend/src/components/PreviewSettingsSection.tsx) (+ `.css`) | Preview settings group ([UI Screens §5](./spec/ui-screens.md#5-preview-settings-screen), [Settings §3](./spec/settings-spec.md#3-preview-settings)): aspect ratio selector + folder-preview frame count (persisted via `/api/preview-settings`, applied immediately); a construction-set grid editor (small/enlarged-2×2/enlarged-3×3 brushes, fill all/clear all) whose canonical tile geometry is fetched live from `POST /api/preview-layouts/preview` (single source of truth shared with the backend renderer) and rendered on a black `LayoutCanvas` with a caption bar, doubling as both editor and live preview; a built-in + custom preset gallery (mini `LayoutCanvas` thumbnails), timeline flow, and identity-diversity toggle, all backed by `/api/preview-layouts` CRUD. Quick save/load slots are not a separate concept: they're just regular (non-builtin) presets with the fixed names `Quick 1`/`Quick 2`/`Quick 3`, created-or-updated by name — no schema or endpoint changes needed to add more slots, just more fixed names on the frontend. |
| [`frontend/src/components/TaggingSettingsSection.tsx`](../frontend/src/components/TaggingSettingsSection.tsx) | Tagging settings group ([Settings §5](./spec/settings-spec.md#5-tagging-settings), [UI Screens §7](./spec/ui-screens.md#7-tagging-settings-screen)): tag vocabulary editor (add/rename-on-blur/activate-deactivate/delete, backed by `useTags()` and `/api/tags`) plus sampled-frame count, combine-into-collage toggle, top-tag count, and a default-provider/vision-model shortcut (persisted via `/api/tagging-settings`, applied immediately like preview settings). |
| [`frontend/src/components/ProviderSettingsSection.tsx`](../frontend/src/components/ProviderSettingsSection.tsx) | AI provider settings group ([Settings §6](./spec/settings-spec.md#6-ai-provider-settings), [UI Screens §10](./spec/ui-screens.md#10-provider-settings-screen)): one row per fixed provider (OpenRouter/Gemini/FAL/Mistral) with enabled toggle, write-only API key field (never pre-filled — only a "key is set" hint from `has_api_key`), vision/text model fields, and a batch-preference toggle; `PUT`s `/api/settings/providers/{name}` per field edit. |
| [`frontend/src/components/BackupMaintenanceSection.tsx`](../frontend/src/components/BackupMaintenanceSection.tsx) ([Stage 8](./spec/roadmap.md#stage-8--backup-restore-maintenance-source-switching), [UI Screens §11](./spec/ui-screens.md#11-backup-and-maintenance-screen), [Settings §7-8](./spec/settings-spec.md#7-backup-settings)) | Backup & Maintenance settings group: backup list (`GET /api/backups`) with per-entry Restore/Delete, a "create backup" action (`include_secrets` checkbox, `POST /api/backups`) and retention count (`GET/PUT /api/backup-settings`), plus three maintenance action buttons (`POST /api/jobs/rescan-directory` with an empty path for a full rescan, `POST /api/jobs/cleanup-stale-records`, `POST /api/jobs/optimize-database`). Backup/restore both create jobs, so the section watches `useJobs()`'s polled `jobs` list for the job id it just started and auto-refreshes the backup list once that job leaves `queued`/`running`, instead of polling the list itself. |
| [`frontend/src/components/InterfaceSection.tsx`](../frontend/src/components/InterfaceSection.tsx) | Interface settings group: language picker and, since [Stage 9](./spec/roadmap.md#stage-9--polish-and-optional-features), a Strict/Playful theme picker (same button-group pattern), both backed by `useInterfaceSettings()` (`InterfaceSettingsContext.tsx`) instead of talking to `i18next`/`localStorage` directly. |
| [`frontend/src/components/JobsModal.tsx`](../frontend/src/components/JobsModal.tsx) (+ `.css`) | Jobs modal ([UI Screens §3](./spec/ui-screens.md#3-jobs-modal)): jobs grouped into running/queued/failed/cancelled/completed sections from `useJobs()`; per-row cancel/restart/remove actions (shown only when valid for the job's status) plus a "clear finished" footer action and a per-row "view log" button that opens `LogViewerModal` filtered to that job. |
| [`frontend/src/components/LogViewerModal.tsx`](../frontend/src/components/LogViewerModal.tsx) (+ `.css`) | Log viewer ([UI Screens §4](./spec/ui-screens.md#4-log-viewer)): job/file/level filter controls, backfills from `GET /api/logs` then appends events from an `EventSource` on `GET /api/logs/stream`, auto-scrolling, capped at the last 500 events client-side. |
| [`frontend/src/components/AppLayout.tsx`](../frontend/src/components/AppLayout.tsx) | Shell layout: top bar + directory-tree pane (`DirectoryTree`, or a "configure a source" placeholder) + main content (`LibraryView`, or an empty state with `BackendStatusPanel`) + `SettingsModal` + `JobsModal`. Owns the selected-folder path *and* the `activeSearch` state (an `ActiveSearch \| null` from `LibrarySearchBox.tsx`) shared between `TopBar` (renders the search box, calls `onSearch`/`onClearSearch`) and `LibraryView` (renders the results). The tree pane (`.app-nav`) is a collapsible inline panel closed by default at every breakpoint (user request — previously it was a persistent always-open pane on desktop, `>=1024px`); it only expands via the top bar's menu toggle, same as the tablet behavior before this change. On mobile (`<640px`) it's still a fixed-position drawer overlay with a backdrop. |
| [`frontend/src/components/DirectoryTree.tsx`](../frontend/src/components/DirectoryTree.tsx) (+ `.css`) | Fetches `GET /api/tree?include_status=true` and renders the recursive, expandable folder tree with conversion/preview indicator dots. Refetches whenever the active source changes. |
| [`frontend/src/components/LibraryView.tsx`](../frontend/src/components/LibraryView.tsx) (+ `.css`) | Fetches `GET /api/directories/children` (server-side filtered to `is_video_supported` files only, so only folders and videos ever appear) for the selected path or, while `activeSearch` (prop, owned by `AppLayout.tsx`) is set, a flat search-results file list from `GET /api/files?tags=`/`?search=` across the whole source. Renders a toolbar (breadcrumb + "rescan" icon button always inline, plus "convert folder"/"generate previews for folder"/"tag folder" — the search box itself now lives in `TopBar.tsx`). Below 640px the convert/preview/tag folder actions collapse into a `MoreVertical` overflow menu instead of three inline icons — both renderings map over the same `directoryActions` array, toggled via CSS (`library-view__actions-inline` hidden, `library-view__overflow` shown). Folder cards show a real `folder-preview.jpg` thumbnail (via `GET /api/directories/preview.jpg?path=`) and file cards show the video's own `<name>.jpg` thumbnail (via `GET /api/files/{id}/preview.jpg`) whenever `previewsVisible` (from `PreviewVisibilityContext`) and the has-preview flag are both true, falling back to the folder/film icon otherwise. File cards were redesigned around two actions (user request, replacing a five-icon row): clicking the thumbnail itself opens `PlaybackModal` to play immediately, and a single small "i" (`Info`) button overlaid on the thumbnail opens `FileInfoPanel` for every other per-file operation (generate preview, tag, convert, similar videos). Folder-level bulk actions ("convert folder" etc.) are unchanged, opening `ConvertDirectoryDialog`/`PreviewDirectoryDialog`/`TagDirectoryDialog`. A job-completion effect (compares `useJobs()`'s `activeJob` against a ref of its previous value; a truthy→`null` transition means a job just finished) bumps a `reloadTick` counter that's in the directory-fetch effect's dependency array, so a freshly generated preview/converted file/tag shows up in the grid without a manual reload or folder re-entry — previously nothing refetched on job completion. `formatSize()` moved to `frontend/src/utils/format.ts` so `FileInfoPanel.tsx` can reuse it without an import cycle. All dialogs/actions refresh `JobsContext` (`refreshJobs`) once a job is created. |
| [`frontend/src/components/FileInfoPanel.tsx`](../frontend/src/components/FileInfoPanel.tsx) (+ `.css`, shares `ConvertDialog.css` for chrome) | Per-file info panel opened from a `FileCard`'s "i" button (user request, replacing the five always-visible per-card icon buttons): shows a larger preview thumbnail, converted/previewed/tagged status lines, and one button per operation — generate preview (`onPreview`, same `POST /api/jobs/preview-file` as before), tag (`onTag`, `POST /api/jobs/tag-file`), convert (`onConvert`, opens `FileConvertModal` and closes this panel), similar videos (`onSimilar`, opens `SimilarFilesModal` and closes this panel). No combobox/dropdown — every operation is a plain button, per explicit user preference. |
| [`frontend/src/components/SimilarFilesModal.tsx`](../frontend/src/components/SimilarFilesModal.tsx) (+ `.css`, shares `ConvertDialog.css` for chrome) | Similar-videos modal: fetches `GET /api/files/{id}/similar` and lists matches (relative path + Hamming-distance "bit difference") or an empty-state message — a normal, non-error outcome, since this is an optional/secondary feature and most files won't have a signature until previews have been (re)generated. |
| [`frontend/src/components/PlaybackModal.tsx`](../frontend/src/components/PlaybackModal.tsx) (+ `PlaybackModal.css`) | Full-viewport playback overlay (redesigned, user request: clicking a video should just play it, with minimal chrome around the video itself rather than a titled dialog). Fetches `GET /api/files/{id}/playback` for the mode + stream URL + direct path, then either renders an HTML5 `<video>` filling the viewport (`object-fit: contain`) against the stream URL (`stream` mode) or shows the direct local/UNC path with a copy-to-clipboard button (`direct_link` mode, since browsers can't open arbitrary local/UNC paths themselves). Only a small floating close button (top-right) and mode-switch button (bottom-right) sit on top of the video; clicking the black backdrop (or Escape) closes it. No longer shares `ConvertDialog.css` — it has its own minimal `playback-overlay__*` styles instead of the shared titled-dialog chrome. |
| [`frontend/src/components/ConvertDirectoryDialog.tsx`](../frontend/src/components/ConvertDirectoryDialog.tsx) (+ `ConvertDialog.css`) | Directory-level convert dialog ([UI Screens §1](./spec/ui-screens.md#1-main-library-screen), [Specification §6.2](./spec/specification.md#62-conversion)): profile picker (from `useConversionProfiles()`), production/test mode radio, skip-processed checkbox; posts `POST /api/jobs/convert-directory`. |
| [`frontend/src/components/FileConvertModal.tsx`](../frontend/src/components/FileConvertModal.tsx) (shares `ConvertDialog.css`) | File-level convert modal with two tabs ([UI Screens §12](./spec/ui-screens.md#12-variant-comparison-flow), [Specification §8.3](./spec/specification.md#83-variant-comparison)): "Convert" (profile/mode/skip-processed, posts `POST /api/jobs/convert-file`) and "Compare variants" (per-row max-dimension/CRF/codec overrides, posts the same endpoint with `mode: "test"` and a `variants` list, then polls `GET /api/jobs/{id}/items` to show each variant's result with a "save as profile" action that `POST`s `/api/conversion-profiles` using the variant's effective parameters). |
| [`frontend/src/components/PreviewDirectoryDialog.tsx`](../frontend/src/components/PreviewDirectoryDialog.tsx) (shares `ConvertDialog.css`) | Directory-level preview dialog: skip-processed checkbox only (no profile picker — the job uses the default layout preset and current global settings); posts `POST /api/jobs/preview-directory`. |
| [`frontend/src/components/TagDirectoryDialog.tsx`](../frontend/src/components/TagDirectoryDialog.tsx) (shares `ConvertDialog.css`) | Directory-level tag dialog: skip-processed checkbox only (provider/vocabulary come from Settings, not per-job); posts `POST /api/jobs/tag-directory`. |
| [`frontend/src/components/BackendStatusPanel.tsx`](../frontend/src/components/BackendStatusPanel.tsx) | Displays `/api/health` and `/api/app/info` (app version, DB schema version, ffmpeg availability); shown in `AppLayout`'s empty state while no source is connected. |
| [`frontend/src/context/PreviewVisibilityContext.tsx`](../frontend/src/context/PreviewVisibilityContext.tsx) | `previewsVisible` boolean + toggle, session-only (not persisted); gates real thumbnail rendering (vs. folder/film icon fallback) in `LibraryView.tsx`, purely client-side. |
| [`frontend/src/context/InterfaceSettingsContext.tsx`](../frontend/src/context/InterfaceSettingsContext.tsx) | Owns `theme` (`strict`/`playful`/`casino` — `casino` added per user request as a third, deliberately loud preset alongside the existing two, not a replacement — applied as `document.documentElement.dataset.theme`) and `language` together, both backed by `GET/PUT /api/interface-settings`: a `localStorage`/browser-locale guess is applied synchronously on first render (avoids a flash of the wrong theme/language), then reconciled against the backend-persisted values once that request resolves. `setTheme()`/`setLanguage()` update local state, `i18next`, `localStorage`, and the backend in one call each — instant, no reload. Wraps the whole app in `App.tsx`, outermost provider. |
| [`frontend/src/context/SourceContext.tsx`](../frontend/src/context/SourceContext.tsx) | Fetches and holds the active source (`GET /api/source`); exposes `refresh()` and `setSource()` (used right after connecting/replacing a source) to the whole app. |
| [`frontend/src/context/JobsContext.tsx`](../frontend/src/context/JobsContext.tsx) | Polls `GET /api/jobs` every 1.5s for the whole app (shared by the top bar and `JobsModal` so they don't poll independently); while a job is queued/running, also polls that job's `GET /api/jobs/{id}/items` on the same interval for the activity indicator's "current item" tooltip. Exposes `jobs`, `activeJob`, `activeJobItems`, `refresh()`. |
| [`frontend/src/context/ConversionProfilesContext.tsx`](../frontend/src/context/ConversionProfilesContext.tsx) | Fetches and holds `GET /api/conversion-profiles` for the whole app; exposes `profiles`, `loading`, `refresh()`. Shared by the Settings profile-management section and both convert dialogs so they stay in sync after create/edit/delete/promote. |
| [`frontend/src/context/TagsContext.tsx`](../frontend/src/context/TagsContext.tsx) | Fetches and holds `GET /api/tags` (the full vocabulary) for the whole app; exposes `tags`, `loading`, `refresh()`. Shared by `TaggingSettingsSection` (vocabulary editor) and `LibraryView`'s search box (client-side prefix filtering for autocomplete) so both stay in sync after add/rename/deactivate/delete. |
| [`frontend/src/hooks/useBackendStatus.ts`](../frontend/src/hooks/useBackendStatus.ts) | Fetches health and app-info endpoints; exposes a loading/error/ready state. |
| [`frontend/src/utils/format.ts`](../frontend/src/utils/format.ts) | `formatSize(bytes)` — shared byte-count formatter used by `LibraryView.tsx` and `FileInfoPanel.tsx`. |
| [`frontend/src/i18n/index.ts`](../frontend/src/i18n/index.ts) | i18next setup; detects initial language from a persisted preference or the browser locale (falls back to English) for the first paint, reconciled against the backend by `InterfaceSettingsContext.tsx` ([Stage 9](./spec/roadmap.md#stage-9--polish-and-optional-features)) once that loads.
