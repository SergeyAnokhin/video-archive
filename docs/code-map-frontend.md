## Notes and conventions

**Copy-to-clipboard buttons**: no shared utility — every instance (`PlaybackModal.tsx`'s copy-path button, `TaggingSettingsSection.tsx`, `LogViewerModal.tsx`'s "copy all" button) inlines the same small pattern instead: `await navigator.clipboard.writeText(text)`, a local `copied` boolean state set `true` then reset via `setTimeout(..., ~1500ms)`, and a `Check`/`Copy` (`lucide-react`) icon swap keyed on `copied`. Reuse this shape rather than re-deriving it or introducing a shared hook for three call sites.

**Adding/removing a theme preset**: `ThemePreset` has no single owner — touch all of these together, or the picker, the cycle toggle, and the backend will disagree:
1. `frontend/src/types/api.ts` — `THEME_PRESETS` array (frontend source of truth; `InterfaceSettingsContext.tsx`'s `detectInitialTheme()` and every consumer below derive from it, no other hardcoded lists to update on the frontend).
2. `frontend/src/styles/theme.css` — new `[data-theme="X"]` variable block (+ optional decorative rules, see the `theme.css` row above for the glow-tier convention).
3. `frontend/src/themeIcons.ts` — `THEME_ICON` entry (shared by `TopBar.tsx` and `InterfaceSection.tsx`; used to be duplicated in both until 2026-07).
4. `frontend/src/i18n/locales/en.json` and `ru.json` — `theme.<key>` label, kept in parity.
5. `backend/app/interface_settings.py` — `THEME_PRESETS` tuple (backend source of truth).
6. `backend/app/routers/interface_settings.py` — the `Literal[...]` on `InterfaceSettingsRequest.theme_preset`, kept in sync with #5 by hand (no shared constant across the Python/TypeScript boundary).
