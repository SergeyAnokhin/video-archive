## Notes, known gaps, and conventions

- **Runtime-created, git-ignored artifacts:** `backend/secrets.env` (created on first write by `secrets_store.py`), `backend/models/` (detection models downloaded on demand), `backend/video_archive.db`.
- **Singleton settings convention:** a global scalar setting gets its own single-row table (`id` fixed to 1) — never a generic key-value table. Step-by-step checklist: [development.md § Recipe](development.md#recipe-adding-a-global-settings-singleton). The `init_db()` seeding hook also serves non-singleton seeds (e.g. `model_pricing.seed_default_prices()`).
- **Non-ASCII paths on Windows:** never use `cv2.imread(path)` (silently returns `None`) — read bytes via `np.fromfile()` + `cv2.imdecode()`; always pass `encoding="utf-8", errors="replace"` to ffmpeg/ffprobe subprocess calls (see `conversion.py`).
- **Known gap:** `HTTPException` bodies are nested under FastAPI's default `{"detail": {"error": {...}}}` rather than a top-level `{"error": {...}}`; no custom exception handler is registered.
- **External-integration caveats:** `fal.py` is best-effort (no fixed response schema; both routes verified live once, 2026-07-16); the default `fal-ai/moondream2/visual-query` follows the score-array prompt poorly — prefer a gateway model for real tagging. Gemini/Mistral batch clients are covered by mocked tests only; a submission/poll failure degrades to per-file tagging. Catalog pricing: only OpenRouter has a machine-readable endpoint (`refresh_openrouter_prices()`); Gemini/Mistral/FAL prices are manual-only. Per-call actual cost is reported only by OpenRouter and FAL's gateway route (`cost_usd_override`); everything else uses the rate-table estimate.
- **SMB costs:** preview/tagging over `smb` download each needed video to a local temp copy per run, with no cross-run caching — acceptable at target archive sizes. SMB code is tested against an in-memory fake of `smbclient` (`tests/conftest.py`), not a real server.
- **Diagnosing "every file fails to probe":** a 100% `"Source is not a probeable video..."` run usually means the backend process can't see ffprobe on `PATH` at all (typically a stale dev-server process predating the ffmpeg install) — restart the backend; see [development.md](development.md).
