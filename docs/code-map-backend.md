Manual/user-defined/tuning assignment helpers plus `replace_scored_tags()` (shared by tag/batch jobs and Tag Lab apply). `resolve_tag_color()` (stored hex or deterministic fallback, same hash as `frontend/src/utils/tagColor.ts`) runs on every tag read; `top_tags_for_directory_subtree()` backs `include_top_tags` in the tree/directories routers. |
| [`backend/app/tag_lab.py`](../backend/app/tag_lab.py) | Tag Lab domain logic: `run_tag_lab()` calls exactly one picked provider entry (no fallback, no batch, bounded by `tagging_settings.request_timeout_seconds`) and returns a `run_id`, the images/prompt sent, the raw reply + full provider JSON, usage, and ranked tags — writing nothing; `prepare_tag_lab()` returns just the images/prompt. A per-file image cache reuses the last-sampled images while tagging settings/vocabulary are unchanged. `apply_tag_lab_result()` is the only writer of `file_tags` and records the apply KPI via `tag_lab_feedback`. `TagLabError` maps to HTTP status in the router and carries the raw response when interpreting it failed. |
| [`backend/app/tag_lab_feedback.py`](../backend/app/tag_lab_feedback.py) | Per-model Tag Lab signals aggregated by `(provider_type, model_name)`: like/dislike tag votes (`tag_lab_tag_feedback`) and an applied-unchanged / applied-with-edits / never-applied KPI derived by diffing `tag_lab_applies` against each run's suggested-tags snapshot. `get_model_stats()`/`get_all_model_stats()` feed Tag Lab's model picker and `GET /settings/model-ratings`. |
| [`backend/app/tagging_settings.py`](../backend/app/tagging_settings.py) | Tagging settings singleton: `sample_frame_count`, `combine_into_collage`, `top_tag_count`, `image_resolution` (px sent to the AI provider per image), `request_timeout_seconds` (Tag Lab's direct-call timeout, forwarded to the provider client; unset falls back to the provider module's own `TIMEOUT_SECONDS`). |
| [`backend/app/provider_entries.py`](../backend/app/provider_entries.py) | User-managed, priority-ordered AI provider entry CRUD (`PROVIDER_TYPES` = openrouter/gemini/fal/mistral; any number of entries per type). `reorder_entries()` rewrites `sort_order` (the fallback priority). Reads expose `has_api_key`/`key_suffix` via `secrets_store`, never the key. |
| [`backend/app/tagging.py`](../backend/app/tagging.py) | Tag-job frame preparation: `sample_frames()` + `build_tagging_images()` → one composed collage or one JPEG per frame, each capped at the configured `image_resolution` (collage cell side / per-frame longest side), ready to attach to a provider request. `load_image()` + `build_tagging_images_for_file()` (dispatcher) extend this to standalone images (post-V1, user request) — a single image is sent as one JPEG at `image_resolution`, no ffprobe/frame-sampling involved. |

[`openrouter.py`](../backend/app/providers/openrouter.py)/[`mistral.py`](../backend/app/providers/mistral.py): OpenAI-compatible chat completions (OpenRouter opts into `usage.cost` → `UsageInfo.cost_usd`); [`gemini.py`](../backend/app/providers/gemini.py): `generateContent`; [`fal.py`](../backend/app/providers/fal.py): best-effort, dual-routed by model string — a literal `fal-ai/...` app path is called directly, any other `vendor/model` id goes through FAL's `openrouter/router/vision` gateway (which also reports `cost_usd`). `list_models()` on openrouter/gemini/mistral; `create_batch()`/`poll_batch()` on gemini/mistral only. ## Notes, known gaps, and conventions

- **Runtime-created, git-ignored artifacts:** `backend/secrets.env` (created on first write by `secrets_store.py`), `backend/models/` (detection models downloaded on demand), `backend/preview_cache/`, `backend/video_archive.db`.
- **Singleton settings convention:** a global scalar setting gets its own single-row table (`id` fixed to 1) — never a generic key-value table. Step-by-step checklist: [development.md § Recipe](development.md#recipe-adding-a-global-settings-singleton). The `init_db()` seeding hook also serves non-singleton seeds (e.g. `model_pricing.seed_default_prices()`).
- **Non-ASCII paths on Windows:** never use `cv2.imread(path)` (silently returns `None`) — read bytes via `np.fromfile()` + `cv2.imdecode()`; always pass `encoding="utf-8", errors="replace"` to ffmpeg/ffprobe subprocess calls (see `conversion.py`).
- **Known gap:** `HTTPException` bodies are nested under FastAPI's default `{"detail": {"error": {...}}}` rather than a top-level `{"error": {...}}`; no custom exception handler is registered.
- **External-integration caveats:** `fal.py` is best-effort (no fixed response schema; both routes verified live once, 2026-07-16); the default `fal-ai/moondream2/visual-query` follows the score-array prompt poorly — prefer a gateway model for real tagging. Gemini/Mistral batch clients are covered by mocked tests only; a submission/poll failure degrades to per-file tagging. Catalog pricing: only OpenRouter has a machine-readable endpoint (`refresh_openrouter_prices()`); Gemini/Mistral/FAL prices are manual-only. Per-call actual cost is reported only by OpenRouter and FAL's gateway route (`cost_usd_override`); everything else uses the rate-table estimate.
- **SMB costs:** preview/tagging over `smb` download each needed video to a local temp copy per run, with no cross-run caching — acceptable at target archive sizes. SMB code is tested against an in-memory fake of `smbclient` (`tests/conftest.py`), not a real server.
- **Diagnosing "every file fails to probe":** a 100% `"Source is not a probeable video..."` run usually means the backend process can't see ffprobe on `PATH` at all (typically a stale dev-server process predating the ffmpeg install) — restart the backend; see [development.md](development.md).
