## `backend/` — FastAPI

| Path | Role |
| --- | --- |
| [`backend/package.json`](../backend/package.json) | Wraps the Python startup (`pip install` + `uvicorn --reload`, host `0.0.0.0`) so the root `npm run dev` can start it. |
| [`backend/requirements.txt`](../backend/requirements.txt) | Python deps: FastAPI, Uvicorn, SQLAlchemy, sse-starlette, python-dotenv, pytest, `opencv-python-headless`/`onnxruntime`/`Pillow`/`numpy` (previews), `httpx` (provider calls + `TestClient` + `sources/webdav_backend.py`), `smbprotocol` (its bundled `smbclient` is what `sources/smb_backend.py` uses), `psutil` (system stats). |
| [`backend/app/main.py`](../backend/app/main.py) | FastAPI app: on startup runs `init_db()`, checks ffmpeg once, probes hardware encode (`hardware_accel.check_hardware_accel()`) and decode (`hardware_decode.check_hardware_decode()` + `log_status()`), requeues stalled batch-tagging jobs, reaps orphaned jobs, starts the `JobWorker` and the `ResourceMonitor`, wires every router, adds `RequestLoggingMiddleware`. |
| [`backend/app/logging_config.py`](../backend/app/logging_config.py) | `configure_logging()`: console + size-rotating-file (`logs/backend.log`, or under `VIDEO_ARCHIVE_STATE_DIR`) handlers, starting from `log_rotation_settings`' hardcoded defaults; disables `uvicorn.access` (superseded by `request_logging.py`). `apply_rotation_settings(max_bytes, backup_count)` mutates the live handler in place (`main.py`'s `lifespan()` calls it once with the persisted DB values after `init_db()`, and the settings router calls it again on every `PUT`). The `RESOURCE_MONITOR_LOGGER_NAME` (`app.resource_monitor`) logger propagates into the same handlers — no separate log file; its lines are marked with a leading 📊 (see `resource_monitor.py`) so they're easy to spot among regular traffic. |
| [`backend/app/resource_monitor.py`](../backend/app/resource_monitor.py) | `ResourceMonitor` (chat request: diagnose Kubernetes OOM restarts silently killing running jobs — see `jobs/service.reap_orphaned_jobs()`): one daemon thread, same start/stop/loop shape as `jobs/worker.py`'s `_Lane`, sampling `routers.system_stats.get_system_stats()` on `resource_monitor_settings`'s interval, re-read from the DB every tick so a Settings change takes effect on the next tick without a restart. Every sample derives a network bytes/sec rate from the delta against the previous sample's cumulative `smb_bytes_transferred_total` and is always written via `resource_monitor_history.record_sample()` for the Settings → Performance history chart; the settings' `enabled` flag only gates an *additional* `logs/backend.log` line (📊-prefixed) — turning it off quiets the log without losing history (chat request 2026-07-25). |
| [`backend/app/resource_monitor_settings.py`](../backend/app/resource_monitor_settings.py) | Resource-monitor settings singleton: `enabled` (default on — gates the `backend.log` line only, not history recording), `interval_seconds` (default 30, clamped 1-3600, applies to both). |
| [`backend/app/resource_monitor_history.py`](../backend/app/resource_monitor_history.py) | Backs the Settings → Performance CPU/memory/network history chart (chat request 2026-07-25). `resource_monitor_samples` table (migration 46), pruned to the last 24h (`RETENTION_SECONDS`) on every write. `get_history(engine, range_seconds)` returns 0-100 percentages for all three signals; network has no natural ceiling so it's normalized against the highest throughput seen in the last 24h (not just the requested range). A range with more raw rows than `MAX_CHART_POINTS` (200) is downsampled into fixed-width buckets taking the **max** of each signal per bucket (not an average), so brief spikes stay visible. |
| [`backend/app/log_rotation_settings.py`](../backend/app/log_rotation_settings.py) | `backend.log` rotation settings singleton: `max_bytes` (default 5 MB, clamped 1-100 MB), `backup_count` (default 5, clamped 1-20 — 0 would never rotate under stdlib `RotatingFileHandler` semantics). |
| [`backend/app/request_logging.py`](../backend/app/request_logging.py) | `RequestLoggingMiddleware`: one log line per request, except the polling routes in `_QUIET_ROUTES` which stay silent unless they error. See `docs/development.md` § Backend console logging. |
| [`backend/app/config.py`](../backend/app/config.py) | App version, `STATE_DIR` (defaults to `backend/`, overridden by `VIDEO_ARCHIVE_STATE_DIR` — see `docs/deployment.md`), SQLite DB path, `SECRETS_PATH`, `PREVIEW_CACHE_DIR`. |

| [`backend/app/db.py`](../backend/app/db.py) | SQLite via SQLAlchemy Core: ordered `MIGRATIONS` map + single-row `schema_meta`; `init_db()` runs pending migrations then seeds default settings rows. | [`backend/app/secrets_store.py`](../backend/app/secrets_store.py) | The only reader/writer of git-ignored `backend/secrets.env`: provider API keys (`PROVIDER_ENTRY_<id>_API_KEY`) and per-source SMB credentials. | [`backend/app/ffmpeg.py`](../backend/app/ffmpeg.py) | Locates ffmpeg on `PATH` and reads its version (startup availability check only). |
| [`backend/app/hardware_accel.py`](../backend/app/hardware_accel.py) | `check_hardware_accel()` — analogous startup probe for Intel QSV/VAAPI hardware encoders, but runs a real 1-frame encode per backend (not just `ffmpeg -encoders` parsing) since build support and a working iGPU/driver are different questions; cached `HardwareAccelStatus(qsv, vaapi)`, exposed via `/app/info`. |
| [`backend/app/hardware_decode.py`](../backend/app/hardware_decode.py) | `check_hardware_decode()` — same real-probe/cache shape as `hardware_accel.py`, but for QSV/VAAPI hardware *decode* (separate from encode availability): decodes a throwaway software-encoded clip per backend. Decode output is bit-identical to software decode (no quality tradeoff, unlike encode), so `app/preview.py` uses it automatically with no per-profile setting. `log_status()` logs the result once at startup (`app/main.py`); cached `HardwareDecodeStatus(qsv, vaapi)`. |
| [`backend/app/conversion.py`](../backend/app/conversion.py) | ffmpeg/ffprobe building blocks: `probe_media()`, `effective_max_dimension()`, `build_ffmpeg_command()` (`preset` param appends ffmpeg `-preset`, skipped when `has_hw_mapping()` says the resolved encoder is a hardware one — qsv/vaapi don't share x264/x265's preset vocabulary), `run_ffmpeg()` (Popen with `-progress pipe:1` → `on_progress(percent)` callbacks and a `should_stop()` poll that kills the process on cancel/pause), `validate_converted_output()`, `encode_variant_suffix()`. `resolve_encoder()`/`_HW_CODEC_INFO` map `(codec, hardware_accel)` to the actual QSV/VAAPI ffmpeg encoder, falling back to the software encoder when unmapped. Reused by preview/tagging/similarity, the media-info endpoint, and `conversion_script.py`. |
| [`backend/app/mp4_probe.py`](../backend/app/mp4_probe.py) | `probe_media(access, rel_path, size_bytes)` — header-only MP4/MOV/M4V fast path for the media-info endpoint: walks top-level ISO-BMFF boxes via `SourceAccess.open_range()` (seek+range reads, no `local_copy()`/download), reads only `moov` (capped 32 MB) for `mvhd` duration + first video `trak`'s `stsd` sample entry (width/height/codec fourCC), approximates `bit_rate` as `size_bytes*8/duration`. Returns `None` (never raises) on anything it isn't sure about — fragmented/`mvex` mp4, no video track, unmapped codec fourCC, malformed box sizes — so the caller always has a safe fallback to `local_copy()` + real ffprobe. Runs for every protocol (local and SMB alike), not just SMB. |
| [`backend/app/media_probe.py`](../backend/app/media_probe.py) | `probe_and_cache(engine, access, file_id, relative_path, extension, size_bytes, modified_at)` — the one-probe-attempt building block shared by `routers/files.py`'s lazy media-info endpoint (which wraps it in its own retry-after-sleep loop) and `jobs/rescan.py`'s `rescan_with_media_info` bulk pass: `mp4_probe` fast path, `conversion.probe_media()` (ffprobe) fallback, guarded persist to `files`' migration-37 columns. |
| [`backend/app/conversion_profiles.py`](../backend/app/conversion_profiles.py) | Conversion profile CRUD; setting `is_default` clears it on all others. `hardware_accel` (`off`/`qsv`/`vaapi`, default `off`) selects an optional Intel hardware encoder, resolved/validated per-job by `jobs/convert.py`. `preset` (migration 41, default `medium`, one of the 9 standard x264/x265 speed presets) is a plain profile field consumed by `conversion.build_ffmpeg_command()`. |
| [`backend/app/conversion_script.py`](../backend/app/conversion_script.py) | Backs `POST /jobs/generate-conversion-script` (user request: a standalone script to run conversion outside the app over SMB): `enumerate_directory_files()` mirrors `jobs/convert.py`'s directory-scope query/`is_test_artifact` filter; `generate_powershell_script()` reuses `conversion.resolve_encoder()`/`has_hw_mapping()` and `jobs.convert._effective_params()` to render a `.ps1` whose `Convert-OneFile` function replicates production-mode's safe-replace guarantee (encode to a same-directory temp file, verify ffmpeg's exit code and a non-empty result, atomic `Move-Item` over the source, leave the source untouched on failure). |
| [`backend/app/orphan_previews.py`](../backend/app/orphan_previews.py) | `find_orphaned_previews(engine, access, directory_id, directory_relative_path)` — backs the "delete orphaned previews" directory action (user request): lists `.jpg` files physically present directly in a directory (non-recursive) that aren't a known video's collage and aren't a genuine tracked standalone image. | [`backend/app/sources/`](../backend/app/sources/) | Uniform file-access layer — all file access goes through here instead of raw `pathlib`: [`entries.py`](../backend/app/sources/entries.py) (shared dataclasses), [`local_backend.py`](../backend/app/sources/local_backend.py) (thin passthroughs), [`smb_backend.py`](../backend/app/sources/smb_backend.py) (`smbclient` over UNC, `_with_retry()` re-registers the session once, temp-file `local_copy()`/`commit_new_file()` (`local_copy()` takes an optional `on_copy_start` callback, fired only on the temp-download branch — never on the UNC fast path or `LocalBackend`'s passthrough — so callers can log "copying locally" + elapsed time around a slow SMB download without the read-side layer knowing about jobs/logging itself); every read/write feeds [`smb_stats.py`](../backend/app/sources/smb_stats.py)'s cumulative byte counter for the network gauge; `direct_access_status()` reports whether the fast path is actually in effect right now — `None` if `direct_access_enabled` is off, else the same cached `windows_unc.available()` probe `local_copy()` itself checks; `commit_new_file()`/`remote_rename()`/`remote_remove()` take a matching opt-in `allow_direct` kwarg — `True` (only ever passed by `jobs/convert.py`, gated on the global `conversion_settings.direct_write_enabled`) does a raw `os.replace()`/`os.remove()` on the UNC path instead of a smbclient upload/rename/remove, falling back to the smbclient call on any `OSError`; every call serializes through the process-wide `_smb_lock` — see its `get_lock_status()`/`force_release_lock()` doc row in [architecture.md](architecture.md)), [`windows_unc.py`](../backend/app/sources/windows_unc.py) (opt-in, Windows-only capability probe — `available(host, share, username, password)` shells out to `net use` to confirm/establish an OS-level SMB session, cached per `(host, username)` with separate re-check TTLs for a positive/negative result; `SMBBackend.local_copy()` uses it to yield the real `\\host\share\...` UNC path directly instead of downloading, when the source's own `direct_access_enabled` flag is on — falls back to the normal download on any failure, never raises), [`webdav_backend.py`](../backend/app/sources/webdav_backend.py) (hand-rolled `httpx.Client` + stdlib `xml.etree.ElementTree`, no third-party WebDAV library, no shared-connection lock; `PROPFIND` depth 0/1 for stat/scandir, `GET`+`Range` for `open_range()`, `PUT`/`MKCOL`/`DELETE`/`MOVE` for writes; `remote_rmdir()` pre-checks the directory is empty since a plain `DELETE` on a WebDAV collection is otherwise recursive; `verify_ssl` (default on) is the per-source opt-out of TLS certificate verification, for a server like Synology DSM's WebDAV Server using a self-signed certificate — see [`docs/webdav-setup.md`](webdav-setup.md)), [`access.py`](../backend/app/sources/access.py) (`SourceAccess` facade + `get_source_access()` factory; `direct_access_status()` passthrough, `smb`-only — always `None` for `local`/`webdav`). |
| [`backend/app/jobs/service.py`](../backend/app/jobs/service.py) | Job/job-item CRUD and the `queued → running → paused → completed\|failed\|cancelled` state machine. `log_event()` writes `app_events` and mirrors errors/warnings to the console with `[#N]` file indices (plus a narrow `_CONSOLE_INFO_EVENT_TYPES` allowlist of info-level events worth seeing live while a job runs — per-item start/progress, the one-line `job_parameters` summary emitted right after a convert/preview job's "Job started.", etc.); in-memory cancel/pause registries + `check_stop_requested()` (the single cooperative checkpoint; a second cancel force-finishes a stuck job); `update_job_item_progress()` (throttled live progress), `run_retention_sweep()` (24h), `_resolve_scope_labels()` (file-scope `scope_ref` → path `scope_label`), `reap_orphaned_jobs()` (startup: fails jobs left `running` by a dead process so they become restartable). `claim_next_queued_job()` (called from `jobs/worker.py`) claims+starts a job atomically in one `UPDATE ... RETURNING`, not a `SELECT` then a separate write — see [architecture.md](architecture.md). |
| [`backend/app/jobs/worker.py`](../backend/app/jobs/worker.py) | `JobWorker` — two `_Lane` threads: CPU lane (everything except `tag`) and network lane (`tag`), claiming only their own job types. Handlers run on a joinable side thread; a force-cancelled job is abandoned (`job_force_abandoned`) instead of wedging the lane. |
| [`backend/app/jobs/rescan.py`](../backend/app/jobs/rescan.py) | `run_rescan_job()` handles both `"rescan"` and `"rescan_with_media_info"` (user request) — same handler, dispatched by `job["job_type"]`: walk the target subtree, batch-upsert, per-file job items, remove stale rows; the `_with_media_info` variant additionally calls `media_probe.probe_and_cache()` per video file whose cache is still empty after the upsert (an unchanged file's existing probe is left alone, so re-running on an already-probed library is cheap). |
| [`backend/app/jobs/convert.py`](../backend/app/jobs/convert.py) | `convert` handler. Directory scope: recursive, skip-processed, `parallel_workers` files per batch; file scope: one production/test conversion or a variant sweep. Safe replace: encode to temp → validate → commit only on success and only if the source shrinks by `min_size_reduction_percent` (else `ConversionSkipped`, warning, source untouched; variants exempt; test mode renames the original). ## Notes, known gaps, and conventions

- **Runtime-created, git-ignored artifacts:** `backend/secrets.env` (created on first write by `secrets_store.py`), `backend/models/` (detection models downloaded on demand), `backend/video_archive.db`.
- **Singleton settings convention:** a global scalar setting gets its own single-row table (`id` fixed to 1) — never a generic key-value table. Step-by-step checklist: [development.md § Recipe](development.md#recipe-adding-a-global-settings-singleton). The `init_db()` seeding hook also serves non-singleton seeds (e.g. `model_pricing.seed_default_prices()`).
- **Non-ASCII paths on Windows:** never use `cv2.imread(path)` (silently returns `None`) — read bytes via `np.fromfile()` + `cv2.imdecode()`; always pass `encoding="utf-8", errors="replace"` to ffmpeg/ffprobe subprocess calls (see `conversion.py`).
- **Known gap:** `HTTPException` bodies are nested under FastAPI's default `{"detail": {"error": {...}}}` rather than a top-level `{"error": {...}}`; no custom exception handler is registered.
- **External-integration caveats:** `fal.py` is best-effort (no fixed response schema; both routes verified live once, 2026-07-16); the default `fal-ai/moondream2/visual-query` follows the score-array prompt poorly — prefer a gateway model for real tagging. Gemini/Mistral batch clients are covered by mocked tests only; a submission/poll failure degrades to per-file tagging. Catalog pricing: only OpenRouter has a machine-readable endpoint (`refresh_openrouter_prices()`); Gemini/Mistral/FAL prices are manual-only. Per-call actual cost is reported only by OpenRouter and FAL's gateway route (`cost_usd_override`); everything else uses the rate-table estimate.
- **SMB costs:** preview/tagging over `smb` download each needed video to a local temp copy per run, with no cross-run caching — acceptable at target archive sizes. SMB code is tested against an in-memory fake of `smbclient` (`tests/conftest.py`), not a real server.
- **Diagnosing "every file fails to probe":** a 100% `"Source is not a probeable video..."` run usually means the backend process can't see ffprobe on `PATH` at all (typically a stale dev-server process predating the ffmpeg install) — restart the backend; see [development.md](development.md).
